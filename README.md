# 2026年米国上院選挙・インタラクティブマップ

2026年の連邦上院選挙について、改選議席の現保有党、情勢評価の取得状態、州詳細、100議席から計算する単純な多数派シミュレーションを表示する静的Webアプリです。D3 geo＋SVGと `us-atlas` の実際の州境を使用し、閲覧時の外部API通信はありません。

> **データ基準日・確認日：2026-09-09。** 全100議席の現職名、党籍、会派、空席、Class、議席任期を一次資料で確認済み。通常33・特別2選挙の日程・対象議席・任期規定と現副大統領も確認しました。候補者、情勢評価、州別解説、出来事年表は未調査・未作成です。確認方法・更新した現職2件・出典は [DATA_VERIFICATION.md](DATA_VERIFICATION.md) を参照してください。

## iPadのSafariで公開版を見る

公開サイトは [上院の行方](https://guchio2366-dev.github.io/us-midterms-2026/) です。Pagesの初期設定とPR #2の配備は完了済みで、以後は `main` の更新ごとにActionsがテスト・ビルド・公開を実行します。下記の初回手順は、別リポジトリで新しく公開する場合の参考です。

### iPadだけで行う初回公開手順

1. SafariでGitHub上のこのリポジトリを開き、対象PRを開きます。
2. PR下部の緑色の **Merge pull request** を押し、続けて **Confirm merge** を押します。
3. リポジトリ上部の **Settings** を押します。見つからない場合は上部メニューを横へスクロールするか、**…** メニューを開きます。
4. Settingsの左側メニューから **Pages** を押します。iPadで左メニューが隠れている場合は左上のメニューボタンを押します。
5. **Build and deployment** の **Source** で **GitHub Actions** を選びます。`Deploy from a branch` は選びません。
6. 上部の **Actions** を開き、左側から **Deploy to GitHub Pages** を選びます。PRのマージで自動実行されていれば、緑のチェックが付くまで待ちます。
7. 自動実行されていない場合は **Run workflow** → Branch: `main` → **Run workflow** を押します。
8. 完了した実行結果を開き、`deploy` または **View deployment** に表示されるURLを押します。そのURLをSafariのブックマークやホーム画面へ追加できます。

Actionsが失敗した場合は、赤い×の付いた実行を開き、失敗した手順名を確認してください。`Settings` や `Merge pull request` が表示されない場合は、そのリポジトリへの管理・書き込み権限を持つGitHubアカウントでログインしているか確認してください。

### 公開後の更新

新しい変更を `main` にマージすると同じworkflowが再実行され、同じURLが更新されます。毎回Pages設定をやり直す必要はありません。反映には数分かかる場合があります。

画面上では、州をタップするか「州を検索・選択」から選ぶと詳細が開きます。「現保有党／選挙情勢」で色の意味を切り替えられ、ページ下部の「全35対象議席の仮定を変更」から多数派シミュレーションを試せます。なお、州別原稿や候補者など未確認の項目は完成情報のように見せず、そのまま「未確認／未作成」と表示しています。

### 古い「33議席」の画面が表示される場合

今回の画面上部には「通常33件・特別2件・対象35議席」「版 verified01-2026-09-09」と表示されます。「一次資料の再確認待ち」の帯や古い版が残る場合は、GitHub Pagesの配備状況とSafariのキャッシュを確認します。

1. 先にGitHubのActionsで最新の **Deploy to GitHub Pages** が緑のチェックになっていることを確認します。
2. 公開ページ上部の **最新版を再読み込み** を押します。このボタンはURLへ一時的な更新番号を付け、Safariに最新HTMLを取り直させます。
3. ボタン自体がまだ表示されない旧版では、Safariのアドレス末尾に `?refresh=1` を加えて開き直します（例：`.../us-midterms-2026/?refresh=1`）。

通常選挙は33件のまま正しく、これにFL-3・OH-3の特別選挙2件を加えた**一意な対象議席数が35**です。

## GitHub Pagesの構成

- `vite.config.ts` はリポジトリ名に合わせて `base: '/us-midterms-2026/'` を設定しています。CSS、JavaScript、州境データはこのサブパスから読み込まれます。
- `.github/workflows/deploy-pages.yml` は `main` 更新時または手動実行時に、依存関係のインストール、テスト、ビルド、Pagesへの配置を順に実行します。
- workflowはGitHub公式のPages artifact/deploy Actionsを利用し、`dist/` を公開します。

ローカルのコミットだけでは公開版は更新されません。mainへのマージ後、対応するActions実行の成功と、公開画面の版表示を確認します。

## データ構成と更新

- `src/data/model.ts`: `states`、`seats`、`elections`、`state_profiles`、`events`、`sources` に相当する型。党派と会派、通常／特別、空席、候補未確認、評価未取得を別属性にしています。
- `src/data/verified-roster.ts`: 公式名簿から照合した100人の現職・原表記・Bioguide ID・党籍・個別確認した会派。党籍から会派を自動生成しません。
- `src/data/data.ts`: 50州、100議席、2026年のClass II通常選挙33件とFL-3・OH-3特別選挙2件、州別原稿の状態、資料単位の出典レジストリ、副大統領の前提。
- `public/data/states-10m.json`: `us-atlas@3.0.1` の州境TopoJSON。npmパッケージのBSD-3-Clause条件に従います。
- `src/logic.ts`: 構造検証、現在構成、仮定結果、多数派表示。地図フィルターとは独立しています。

更新時は、重要な主張ごとに `sources` へ資料名・発行主体・URL・対象期間・取得日を追加し、各レコードの `sourceIds` から参照してください。取得日と資料の更新日を混同せず、基準日以後の資料を過去時点の説明に混ぜないでください。候補者は `candidates[]` に追加し、候補未確定、該当党候補なし、調査未完了を区別します。特別選挙は新しい `elections` レコードとして追加しますが、同じ `seatId` を新議会集計で二重計上しない確認が必要です。

基礎情報を `confirmed` にするには、`verifiedAt` と全確認項目の `attributeSourceIds` が必要です。参照する資料には実際の取得日と内容確認日を登録します。値を変更したら、以前の確認状態・確認日をそのまま引き継がず再照合してください。出典不足や内容未確認のまま確認済みにすると `validateData` がエラーにします。

## 表示の意味

- **現保有党**：2026年対象議席の現在の党派。州全体の党派傾向や予測ではありません。
- **選挙情勢**：単一機関の分類を表示する欄。現データでは全件「未取得」であり、安全議席や接戦に補完していません。
- **激戦のみ強調**：Toss Up＋Lean D/Rだけを強調する表示フィルター。集計対象は変わりません。
- **★**：FL-3・OH-3に収録した特別選挙の重ね記号。通常選挙とは別レコードですが、議席は一意に集計します。
- **議席の6年任期**：議席自体のサイクルです。途中就任した議員本人の在職期間と区別します。特別選挙の当選者の就任日は未定、残任期の終了日は2029-01-03です。
- **シミュレーション**：非改選65議席と通常33・特別2の計35対象議席の仮定会派を議席単位で合算します。初期状態は現保有会派の維持仮定で、予測・勝率ではありません。51議席以上と、50議席＋副大統領決裁票の前提を区別します。
- **副大統領**：現職のJD Vance（共和党）は確認済み。2027-01-03にも在職し所属党側へ決裁票を投じるという仮定を別途明示します。
- 州の面積は議席数を表しません。アラスカとハワイは `geoAlbersUsa` により位置・縮尺が調整されています。D.C.は上院議席がないため集計・地図から除外しています。

## 出典方針

制度・議席Classは [U.S. Senate](https://www.senate.gov/senators/Classes.htm)、州境は [us-atlas](https://github.com/topojson/us-atlas) を起点とします。州原稿は [Census ACS](https://www.census.gov/acs/www/data/data-tables-and-tools/data-profiles/)、[BLS QCEW](https://www.bls.gov/cew/)、[BEA GDP by State](https://www.bea.gov/data/gdp/gdp-state) 等の実際に使った表へ資料単位で紐付ける設計です。組織トップページだけを主張の根拠にせず、未照合項目は未確認のままにします。情勢評価は利用条件を回避せず、一つの公開・確認可能な機関へ統一してから追加します。
