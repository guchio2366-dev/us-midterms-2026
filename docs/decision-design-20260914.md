# 米国中間選挙2026 改善設計書

> この設計の実装状況は[実装記録](decision-design-implementation-20260914.md)を参照。スマートフォンのニュースは、後続の利用者指定に従い約3件が見える枠内スクロールを維持する。本文は設計時点の記録。

版：1.0　作成日：2026年9月14日

対象：[米国中間選挙2026](https://guchio2366-dev.github.io/us-midterms-2026/)

目的：全国の議席構成を読み取り、ニュースと州別資料を根拠に仮定を置き、その仮定で何が変わるかを比較できるサイトにする。

本書は、2026年9月14日の公開画面レビューと同日の公開ソース確認を基にした実装仕様である。文中の議席数は、サイトが採用している2026年9月13日集計の例であり、実装時にはデータから算出する。本書の作成時点では、サイトの実装・公開作業は行っていない。

## 1. 改修の判断

現行版は、全国情勢の3列表示、地図と州詳細の連携、候補者単位の仮定、自動保存、逆算経路の例示まで整っている。次の改修では、読者が計算や説明の補完に使っている手間を減らす。

| 優先順位 | 改修 | 読者が答えられるようにする問い | 主要な成果物 |
| --- | --- | --- | --- |
| 1 | 全国議席の合計・未配分の理由を明示 | 両会派は何議席に位置し、残り何議席がどの理由で未配分なのか | 合計付き議席バー、未配分の内訳、条件付きの不足議席表示 |
| 2 | ニュースと州解説を判断に必要な文章へ整える | 誰のどんな動きで、候補者や争点の見方がどう変わるのか | 記事の編集仕様、州の短い導入、根拠付きの比較材料 |
| 3 | 逆算案の共通点・代替関係・制約を明示 | この州を選ぶ必要があるのか、別の州に替えると何が変わるのか | 経路比較、交換可能な議席一覧、個別の固定操作 |

### 1.1 設計上の前提

- 冒頭の制度説明と現在の3列構成を土台にし、各欄の情報を改善する。
- 議席構成は横棒グラフで示し、その近くに合計・内訳・基準日を置く。
- 「現在の議席」「情勢評価に基づく暫定配分」「利用者が置いた仮定」を明示する。
- 公開ページは要点を短く示し、候補者資料、調査条件、原資料は必要な箇所から開けるようにする。
- 議席数、分類、日付、候補者名は共通データから表示する。文章に転記した数値で別管理しない。

今回の実装範囲は上記3点とその検証である。下院の選挙区別経路の自動生成、新しい勝率モデル、全面的な画面刷新は別の改修として扱う。

## 2. 全国議席表示の仕様

### 2.1 最初に読ませる内容

全国情勢の左欄は、次の順序にする。

1. 「上院：情勢評価に基づく暫定配分」という見出し。
2. 非改選を含む会派側の合計と、未配分の合計。
3. 既存の全100議席の積み上げ横棒。
4. 未配分の理由別内訳と、目標までの不足議席。
5. 既存の51議席の配分例、集計方法・各機関の評価へのリンク。

2026年9月13日集計を使った表示例は以下とする。

| 主表示 | 内訳 |
| --- | --- |
| **民主党会派側 46** | 非改選34 ＋ 改選で民主党側に分類12 |
| **未配分 6** | 接戦評価一致2 ＋ 評価分裂4 ＋ 評価資料不足0 |
| **共和党会派側 48** | 非改選31 ＋ 改選で共和党側に分類17 |

合計の直近に「非改選を含む暫定配分」を表示する。46・48を確定議席や当選者数と表現しない。本文では「民主党会派」「共和党会派」を使い、D・Rだけの表記は小さな比較表示に限る。

棒の中には非改選と改選の内訳を置く。狭い区間の数字は棒の下に出し、数字を入れるために区間の幅を拡大しない。棒全体の長さは100議席、各区間の幅は議席数に比例させる。

### 2.2 未配分を3種類に分ける

既存の `RatingConsensusCategory` を使い、以下の表示に統一する。

| データの分類 | 画面の短い表記 | 説明 | 基本表示 |
| --- | --- | --- | --- |
| `D` / `R` | 民主党側 / 共和党側 | 採用する2機関の評価方向が一致 | 既存の党派色 |
| `tossup` | 接戦評価一致 | 2機関ともToss Up | 無地の灰色＋文字 |
| `split` | 評価分裂 | 2機関の評価方向が一致しない。D対Rに加え、党派側対Toss Upを含む | 灰色の斜線＋文字 |
| `missing` | 評価資料不足 | 統合に必要な有効な評価が揃っていない | 白地・点線枠＋文字 |

「未配分」は `tossup + split + missing` の合計とする。現行データで資料不足が0でも、集計・画面・シミュレーションは0以外を扱えるようにする。会派非所属・会派未確認・空席はそれぞれ別の状態として扱う。

この分類を、全国の内訳、注目州のラベル、地図の凡例と選挙詳細、逆算の各選挙に共通で使う。全国では評価分裂、州詳細では単にToss Up、といった意味の欠落をなくす。

党派色の濃淡でSolid／Likely／Leanを残す場合、近くに「方向：2機関の統合／強さ：Sabato」を表示する。統合した勝率や平均的な評価強度に見せない。出典別の原分類は詳細で並べる。

### 2.3 不足議席を条件と一緒に示す

次の文を不足議席の直前に置く。

> 各会派側に分類した議席をすべて維持し、未配分の議席を追加で獲得する場合。

| 目標 | 非改選に加えて今回獲得する必要がある議席 | 上記の暫定配分からの追加 |
| --- | --- | --- |
| 民主党会派51 | 17議席 | 未配分6のうち5議席 |
| 共和党会派51 | 20議席 | 未配分6のうち3議席 |
| 共和党会派50 | 19議席 | 未配分6のうち2議席 |

51議席の2本の配分例は現行の位置で示す。共和党50の条件はその近くに短く表示し、副大統領の決裁票を使う想定を同じ箇所に置く。副大統領の所属・確認状態は既存の `vicePresident` データを参照し、未確認なら50の条件を確定的に案内しない。

「50＋副大統領」は、同票を解消する条件として説明する。個別の手続では、最終採決と討論終結などの条件を区別し、既存の手続データを参照する。副大統領による同票の解消は[米国上院の説明](https://www.senate.gov/about/officers-staff/vice-president.htm)、一般的な討論終結の基準は[米国上院の制度説明](https://www.senate.gov/about/powers-procedures/filibusters-cloture.htm)に基づく。

計算は以下に統一する。

```text
会派側の暫定合計 = 非改選の当該会派 + 改選で当該会派側に分類した議席
目標までの追加 = max(0, 目標議席 - 会派側の暫定合計)
今回獲得が必要 = max(0, 目標議席 - 非改選の当該会派)
```

追加が未配分の総数を超える場合、「未配分だけでは届かず、相手側に分類した議席も○議席必要」と表示する。すでに到達している場合は「この暫定配分では目標の目安に到達」とする。この欄は全国の基準を示し、利用者の操作による不足議席はシミュレーション側で表示する。

### 2.4 集計の整合性

- 選挙の重複排除は `seatId` で行う。州が同じでも通常選挙と特別選挙の対象議席を区別する。
- 非改選と改選の議席数の合計、棒の区間の合計、表示する会派・未配分・その他の合計が、議席データの総数と一致する。
- 各集計版で、同じ議席・同じ評価機関の入力を一意にする。配列の最後にあった項目を無条件に最新扱いしない。
- 集計基準日、評価機関ごとの確認日、原資料の公表日が取得できる場合の公表日を区別する。サイトの編集日を評価日として使わない。
- 評価の確認に失敗した場合、直前に確認できた評価とその日付を表示できるようにする。「確認失敗」と「有効な評価が存在しない」は別に扱う。

## 3. ニュース・州解説の編集と表示

### 3.1 記事は読者が得られる情報を主語にする

「判断材料に追加した」「新しい確認点に加えた」などの作業報告を、公開記事の結論にしない。更新履歴には作業内容を記録し、記事では出来事・読み取れる意味・残る不確実性を説明する。

| 部分 | 必須の内容 | 長さの目安 |
| --- | --- | --- |
| 一覧の見出し | 誰が、何をしたか。記事が解説なら何を比較するか | 25〜45字 |
| 一覧の要約 | 出来事の要点と、読者が判断に使える点 | 80〜130字 |
| 記事の冒頭 | 初出の人物の党派・立場・関係する選挙。必要なら対立候補 | 1〜2文 |
| 確認できたこと | 発言・行動・調査結果など、出典から直接確認した内容 | 1段落 |
| 選挙を見るうえでの意味 | 従来の材料と比べ、何を新しく比較・確認できるか | 1段落 |
| まだ分からないこと | 出典から決められない点と、次の判断に必要な資料 | 1〜2文 |
| 原資料 | 出典名、該当資料、出来事・公表・確認の日付 | 本文の該当箇所と末尾 |

文字数は編集の目安とする。出典に必要な条件を削って合わせない。候補者の自己主張、第三者の観測、編集上の解釈は既存の根拠区分で示す。

### 3.2 Paxtonの記事を使った書き換え例

以下は現行記事をもとにした文章構成の例である。実際に公開する本文は、候補者名簿と記事の原資料に照合する。広告開始後の効果を確認した例ではない。

> **Paxton支援団体、テキサス上院選で大型広告の放映を開始**
>
> 共和党のKen Paxtonと民主党のJames Talaricoが争うテキサス州上院選で、Paxtonを支援する団体の広告放映が始まった。
>
> 広告の内容を両候補のこれまでの主張と照らすことで、どの争点を前面に出しているかを比較できる。放映後の候補者認知や好感度の調査は、有権者の受け止めを確かめる材料になる。
>
> 出稿額と広告の到達範囲は同じではない。支持率や得票への効果は、広告開始の事実だけでは判断できない。

記事中で「接戦」「優勢」を使う場合は、採用した評価または調査の時点を併記する。テキサスの統合表示では「評価分裂」という分類を保つ。

### 3.3 出来事・解説・予定を識別する

現行の「最近の動き／今後の予定」の2タブを使う。「最近の動き」の一覧に、出来事と解説のバッジを付ける。

| 種類 | 一覧に載せる内容 | 主に表示する日付 |
| --- | --- | --- |
| 出来事 | 発言、広告開始、調査公表、採決など | 出来事の日付。判明しなければ公表日をその名目で表示 |
| 解説 | 複数の出来事や州を比較する記事 | 掲載日。本文に分析の対象期間 |
| 予定 | 出典がある討論会、投票、発表予定など | 予定日と現地の時刻・時間帯。必要に応じて日本時間 |

「同じ接戦でも、候補者を評価する焦点が異なる」のような比較記事は解説として表示する。作業日を出来事の日付に変換しない。「今後、支持率を確認する」といった観測方針は、州詳細の「次に確かめたい点」に置く。

予定の延期・中止・日程未定・結果確認待ちは、現行の状態区分を使って表示する。予定日を過ぎたという理由だけで実施済みにしない。

日付のない出来事にダミーの日付を入れない。日付のみの記録は現地暦日として保持し、時刻のある記録だけを時間帯に従って変換する。

### 3.4 州詳細の冒頭を統一する

州を開いた直後に、次の内容が180〜260字程度の導入で分かるようにする。

1. 誰と誰が争うのか。現職が出馬していない場合は、現職と候補者を明確に区別する。
2. 情勢評価が何を示しているか。接戦一致・評価分裂・党派側の分類を明示する。
3. 比較の中心となる争点・候補者評価と、その根拠。
4. 現段階で判断が残る点。

既存の「当選者を選ぶ」「候補者比較」「関連ニュース」への移動を導入の近くに置く。初回表示では導入と操作を優先し、根拠の長文は項目ごとに開く。

候補者比較は現在の共通軸を使い、双方を同じ問いで比較する。資料の不足を空欄で表現せず「未確認」と示す。原資料がない説明を文章量を揃えるために補わない。

### 3.5 統計を判断材料として採用する条件

州の統計を主要な判断材料に置く場合は、以下の3点を1組にする。

| 項目 | 記載する内容 |
| --- | --- |
| 州の条件 | 産業、雇用、人口、家計などの事実。時点・単位・分母・出典 |
| 選挙との接点 | 候補者の政策、発言、採決、争点調査など、統計との関係を裏付ける資料 |
| 比較できること | 両候補の対応の違い、政策の対象、負担や便益の範囲など |

例として、住宅関連の産業比率を示すなら、住宅費の統計や候補者の住宅政策に結び付く資料を確認する。産業比率だけから、住宅政策が投票先を左右すると結論づけない。

テキサスの大豆生産量など、今回の候補者や争点との接点を説明できない数値は、州の参考資料へ移す。人口構成から個人の投票先を推定する説明も採用しない。

### 3.6 州内のニュースを1か所にまとめる

「ニュース・今後の予定」「この州に関係するニュース」「関連ニュース」の重複を、州詳細内の「この選挙のニュース・予定」にまとめる。

- 全国の一覧と同じ `NewsFeedKey` と選挙IDを参照する。
- 同じ出来事に対応するニュースと更新記録は、既存の関連IDを使って1件にまとめる。
- 通常選挙と特別選挙を誤って混ぜない。州全体に関係する場合は対象選挙を明示する。
- ニュースから州を開き、記事に戻った際の位置と一覧の絞り込みを保持する。

### 3.7 初回の編集対象

まず注目州と逆算の交換候補に現れる選挙、全国一覧の最新記事を整える。前回レビューで説明不足が見られたニューハンプシャーを優先する。

注目州に出す最小条件は、候補者の関係が分かる導入、評価機関ごとの原分類と確認日、根拠付きの判断材料1件、残る不確実性である。未整備の州も一覧から消さず、「詳説準備中」と確認済みの情報を表示する。解説の量を、接戦度や勝ちやすさの評価に使わない。

## 4. 逆算機能の仕様

### 4.1 比較する対象を明示する

逆算画面は、次の4部分で構成する。

| 部分 | 表示する内容 |
| --- | --- |
| 目標と基準 | 手続、想定会派、必要議席、現在の仮定、不足議席、保存案の基準日 |
| 維持する仮定 | 現在その会派として数えている議席、利用者が固定した選挙と結果 |
| 経路例と差分 | 最大3例、追加する選挙、表示例の共通点、交換できる選挙 |
| プレビュー | 変更前後の各選挙と議席合計、適用・取消・適用後の「直前に戻す」 |

上院の目標を満たした表示から、下院や他の手続の条件まで満たしたと読めないようにする。下院の不足は現在と同じく別表示する。

### 4.2 「共通」と「必要」の定義

| 表示語 | 定義 |
| --- | --- |
| 維持する議席 | この計算で、現在その会派として数えている議席を維持する前提 |
| 表示中の例で共通 | 画面に出した最大3例に共通して含まれる追加議席 |
| 同じ区分で交換できる議席 | 情勢区分を優先する同じ選び方の中で、追加議席を置き換えられる選挙 |
| この条件では獲得が必要 | その選挙の獲得を除外すると、現在の固定条件の下で目標へ到達できないことを計算で確認した議席 |

表示例の共通部分を「必須州」と呼ばない。必要性の判定には、表示した3例だけでなく、固定されていない全対象選挙を使う。「この条件」は会派、目標、維持・固定した仮定を指す。

例えば、追加候補が5議席で必要数が3なら、表示した3例に同じ州が含まれていても、その事実だけでは獲得が必要とはいえない。

### 4.3 計算の単位と入力

画面では州名を使い、計算は議席・選挙IDで行う。`stateFips` だけで経路を作らない。全対象選挙から1議席ずつ追加するモデルを使う。

```text
T = 選択した手続の上院目標議席
H = 現在の仮定で対象会派として数えている全議席
A = 対象会派以外・未配分の改選議席のうち、変更を許している議席
k = max(0, T - H)
```

対象会派として数えている議席は、この計算では維持する。別の会派・未配分などの明示的な指定が固定されていれば、その議席を `A` に含めない。候補者の会派が未確認の場合、氏名だけを理由に対象会派へ数えない。

| 条件 | 表示 |
| --- | --- |
| 上院の数値目標がない | 「この手続には上院の数値条件がない」 |
| `k = 0` | 「現在の仮定で、上院の目安を満たす」 |
| 固定を全て解除しても届かない | 「今回の選挙による議席の変更だけでは目標へ届かない」 |
| 固定があるため `A` が足りない | 「固定した仮定を維持すると、あと○議席足りない」＋該当する固定一覧 |
| 到達できる | 必要な追加数と経路例を表示 |

ある候補議席を `A` から外しても `H + 残る候補数 >= T` なら、その議席を「獲得が必要」と表示しない。将来、候補ごとの追加議席数や制約が変わった場合は、この単純な判定を使わず到達可能性を再計算する。

### 4.4 経路例の生成

現行の `generateSenatePaths()` は、評価順に並べた境界の選挙を回転させて最大3例を作っている。本改修では、順序を少しずらした例が同じ州を過度に共有する状態を減らし、交換候補を全て確認できるようにする。[現行実装](https://github.com/guchio2366-dev/us-midterms-2026/blob/main/src/scenario/paths.ts)

採用する方式は以下とする。

1. 到達可能性は、固定条件を反映した全候補 `A` で判定する。
2. 評価のある候補について、対象会派側から相手会派側へという現行の評価区分の順序を表示上の優先順に使う。同じ区分内の勝率差は仮定しない。接戦評価一致と評価分裂の内訳は保持する。
3. 必要数に達する境界より前の候補と、境界の区分から選ぶ候補を分ける。前者は「この選び方で共通」とする。境界の候補一覧と必要数を、経路カードとは別に表示する。
4. 境界から選ぶ部分では、既出の例への登場回数が少ない候補から必要数を選ぶ。同点は選挙ID順にする。
5. 同じ組合せになった場合、既出例の1議席を未選択の1議席と交換して得られる組合せを調べる。未表示の組合せから、既出候補との重複が少ないものを選ぶ。同点はID順にする。
6. 最大3例で終了する。可能な組合せが1つしかない場合は1例だけを出す。IDの並び順や「例1」を優劣として説明しない。

組合せ全体の列挙は不要である。境界の候補数を `n`、選ぶ数を `b` とすると、同じ選び方の組合せ数は `nCb` で算出できる。表示は「同じ区分から選ぶ○通りのうち3例」とし、到達可能な全経路の総数とは呼ばない。全候補は交換一覧で確認できる。

評価資料不足の議席は勝ちやすさの順序に入れない。原則として評価のある候補で例を作り、資料不足の候補も存在することを併記する。評価のある候補だけでは足りない場合は、「評価資料不足の議席を含む例」と明示して不足分を補う。資料不足の選挙も変更候補・到達可能性・必要性判定から除外しない。

編集上の詳説が未整備であることと、情勢評価の資料が不足していることも分ける。説明が短い州の順位を下げない。

### 4.5 経路カードと交換の表示

各経路カードに以下を表示する。

- 追加する選挙。通常・特別の区別を含む。
- 追加後の上院議席合計と目標との差。
- 追加する議席の情勢区分の内訳。表示名は「情勢区分の構成」とする。
- 他の表示例と異なる選挙。
- その選挙の比較材料1文、未確認事項、根拠へのリンク。

全例に共通する説明はカードの上に1回だけ表示する。交換一覧では「候補者」「2機関の評価」「比較する争点・候補者評価」「根拠の時点」「まだ分からないこと」を同じ項目で並べる。スマートフォンでは同じ項目順の選挙別表示にする。

比較材料は州詳細の `RaceObservation` を参照する。記事や古い `RaceBrief` と別の結論を手書きしない。ニューハンプシャーを含め、資料未整備の選挙には確認済みの評価と「詳説準備中」を表示し、他の候補との交換操作は使えるようにする。

交換一覧では、同じ区分の候補だけでなく「ほかの区分も見る」を開けるようにする。別区分の候補への交換は、情勢区分の構成が変わることを示してプレビューする。

### 4.6 個別の固定・解除

逆算画面から、各選挙の現在の仮定と「この仮定を固定」を操作できるようにする。

- 既存の明示的な候補者・会派指定と `unlockedSeatIds` を使う。
- 候補者を指定済みなら、その候補者IDを保ったまま固定する。
- 初期配分のままの議席を固定する場合、現在の会派または未配分を明示的な指定として保存する。
- 解除では現在の選択結果を維持し、経路から変更できる状態にする。
- 未配分を固定すると、その選挙は自動で配分しない。操作の直近でこの意味を説明する。
- 固定の変更は既存の自動保存と「直前に戻す」の対象にする。

一括解除だけに頼らず、到達を妨げている固定条件を選挙ごとに見直せるようにする。

### 4.7 プレビュー・適用・保存

プレビューではシナリオのコピーから変更後の集計を計算する。適用前には操作中の仮定、自動保存、共有URLの内容を変更しない。

適用する時は、変更する選挙について「現在の候補者・会派 → 新しい会派」を表示し、1回の操作として適用する。自動経路が選ぶのは会派であり、候補者を推測して自動選択しない。変更対象外の候補者指定は保持する。

会派、手続、固定条件、議席の選択、保存案、採用する評価版が変わったら、以前のプレビューを失効させる。適用時には入力の一致と到達数を再確認する。経路IDは配列上の「1番」だけに依存させず、目標・基準版・変更対象の組合せから識別する。

名前付き保存、最大5案の保存、最大3案の比較、共有URL、直前に戻す操作は既存の仕組みに統合する。保存済みの基準版を新しい暫定配分に無断で置き換えない。保存時の基準と現在の評価を併用する場合は、それぞれの日付を表示する。

### 5.2 必要な表示用データ

| 表示モデル | 必要な項目 | 生成元・注意点 |
| --- | --- | --- |
| 全国集計 | 総議席、非改選、改選、会派側合計、未配分3分類、その他、基準版、日付 | 議席と評価の共通集計から生成。二重保存しない |
| 選挙の評価表示 | 選挙ID、統合分類、原分類、機関名、確認日、出典ID | `consensusDisplayRating()` の文字列だけから理由を復元しない |
| 記事表示 | 表示種別、見出し、要約、出来事、意味、不確実性、各日付、関連選挙・候補者、根拠ID | 既存記事と更新のアダプターで統合 |
| 州の導入 | 選挙ID、導入、比較材料、残る不確実性、根拠、更新日 | `RaceObservation.lead / materials / uncertainty` 等を再利用 |
| 経路比較 | 維持する議席、変更候補、固定、追加数、表示例、交換候補、表示例の共通部分、条件上必要な議席 | 現在のシナリオ・目標から計算 |

ニュースの `sourceKind` は `news / update / event` という保存元の区別なので、出来事・解説という意味の分類に使わない。既存の `ResearchNewsItem.kind` で識別できる項目をマッピングし、識別できない記事に限って `editorialType: 'event' | 'analysis'` を追加する。更新記録にも必要に応じて同じ意味区分を持たせる。既存記事の分類は移行時に1件ずつ確認し、日付の有無だけで推測しない。

既存の `ObservationUpdate.happened / meaning / uncertainty` は、それぞれ「確認できたこと／選挙を見るうえでの意味／まだ分からないこと」に対応させる。根拠のない文章を自動生成して項目を埋めない。

経路結果には `candidateSeatIds`、`heldSeatIds`、`commonToDisplayedSeatIds`、`requiredUnderConstraintsSeatIds` 相当の項目を分けて持たせる。既存の `difficulty` は確率や数値的な難易度として使わず、表示では分類の件数として扱う。

### 5.3 URL・保存・閲覧状態

- 既存の選挙ID、ニュースキー、保存案、共有URLの読み込みを維持する。
- 新しいラベルや未配分の内訳は派生表示なので、保存形式に重複して入れない。
- 固定は既存のシナリオ構造で表現する。保存形式の変更が必要になった場合は版を上げ、既存案を変換して復元する。
- 共有で再現するのは適用済みの仮定・目標・基準版とする。適用前のプレビューは保存しない。
- 記事、州詳細、比較、逆算を行き来しても、対象選挙と操作中のシナリオを保持する。
- 閲覧上の開閉やホバーだけで、保存した議席の選択を変更しない。

## 6. 端末幅・表示・操作

### 6.1 表示要素ごとの仕様

| 要素 | 読み取る内容 | 表現 | 狭い画面・代替表示 | 確認する点 |
| --- | --- | --- | --- | --- |
| 全国の議席バー | 全体と改選の構成、未配分 | 議席数に比例する積み上げ横棒と直接ラベル | 合計と理由別内訳を折り返す。棒を伸ばさない | 数字がなくなる区間でも外側の内訳で読める |
| 地図の評価表示 | 選挙の位置と評価区分 | 現行の地図・配色に理由の文字と模様を追加 | 州・選挙一覧からも同じ詳細を開ける | 色や細かい州のタップだけに依存しない |
| 逆算の比較 | 追加する選挙と交換による差 | 最大3例と項目を揃えた比較 | 1例ずつ縦に示し、同じ項目順で比較 | 「共通」と「必要」が読み分けられる |

表示は既存のDOMとSVGを使う。全国バー数本、地図1面、比較最大3例という規模を前提とし、新しい描画ライブラリは追加しない。出典や集計を読めるHTMLを用意し、装飾やホバーがなくても主要な数値・意味が伝わるようにする。

### 6.2 画面幅ごとの読み順

| 画面 | 読み順と動作 |
| --- | --- |
| デスクトップ | 現在の全国3列。各欄の見出しと主要情報を同じ高さで始め、説明の長文は展開する |
| タブレット縦 | 合計・議席バーを読み取れる幅で表示。3列が成立しない幅では、全国集計→注目州→ニュースの順に折り返す |
| スマートフォン縦 | 全国集計→注目州→ニュース。州詳細は導入と当選仮定を上部に置く。比較は選挙ごとに縦表示 |
| スマートフォン横 | 固定バーとダイアログが本文を覆わない高さにする。横向き専用の別操作は増やさない |

タッチ端末では情報をタップまたはフォーカスで開けるようにする。主要な操作領域は44 CSS px程度を目安にし、本文を極端に小さくして収めない。選択中・キーボードフォーカスには、党派色とは別の枠線を使う。

ページ全体に横スクロールを発生させない。資料の詳細表だけ横スクロールを認める場合は、表の領域内で完結させる。モバイルのニュース一覧では過度な入れ子スクロールを避け、件数表示と「続きを見る」で扱えるようにする。

ダイアログは見出し・閉じる操作・フォーカスの戻り先を持つ。選挙の比較や仮定の更新後は、更新した合計へ到達できるようにする。読み上げの通知は合計の短い更新に絞り、記事全文を再通知しない。

新しい遷移・アニメーションは情報の理解に必要なものに限る。印刷やスクリーンショットでも合計、未配分の理由、日付、仮定という区分が残るようにする。
