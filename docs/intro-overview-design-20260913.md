## 3. 掲載原稿

以下は実装時の標準原稿である。制度・争点ともに本文の文体は「だ・である」に統一し、操作ラベルは短い自然な日本語とする。数字を含むラベルの `{{...}}` はデータから置換し、画面にそのまま出さない。

### 3.1 サイトの目的：常時表示する1文

米国中間選挙の情勢と争点を知り、州ごとの当選者を仮定して、議席配分と議会の権限への影響を確かめるサイト。

目安は45〜65文字程度。既存の長い紹介文と重複して表示しない。

### 3.2 制度の説明：図の直前

米国議会は上院と下院から成り、中間選挙は大統領の4年の任期の中間に行われる。2026年は上院の100議席中35議席と、下院の全435議席を選び直す。

実装上は100・35・435を対応する集計値から生成する。上院通常33・特別2の内訳は棒の直下に「通常33＋特別2」と短く添える。435は下院本会議で投票権を持つ議席を対象とする。[上院のClass II](https://www.senate.gov/senators/Class_II.htm)、[米下院の制度説明](https://www.house.gov/the-house-explained)

### 3.3 図の後に置く効用の説明

議席配分が変わると、法案や予算を決め、大統領の政策や人事を進めたり制約したりする議会の力関係が変わる。

直後に「必要な票数や院ごとの役割は、後の『議席と権限』で詳しく説明する。」と置き、項目名をリンクにする。議会と大統領の役割、両院の関与が異なることの詳細は既存の権限表に任せる。[米下院の立法過程の説明](https://www.house.gov/the-house-explained/the-legislative-process)

### 3.4 「選挙を見る主な論点」：通常表示する6文

今回の中間選挙では、トランプ政権の運営や政策への評価が、全国の選挙情勢を左右する大きな要因となる。都市部では民主党、地方部では共和党の支持が強い傾向があり、郊外では支持が分かれている。物価や雇用、移民、医療などは複数の州に共通する論点で、同じ政策でも地域の産業や暮らしによって受け止め方が異なる。

候補者の実績や政策姿勢、地元との関係によって、全国的な党派の傾向と異なる結果になる場合もある。支持する相手が変わることに加え、どの支持層が実際に投票に行くかも結果を左右する。全国の傾向と各州の事情を併せて読むことで、接戦の理由や議席が動く条件を考えやすくなる。

編集時の条件：
- 5〜6文という合意に対し、本書では6文を採用する。見出しやキーワードだけに短縮しない。
- 8論点を開かなくても大枠が理解できる内容にする。既定表示で行数制限・末尾省略・「続きを読む」を使わない。
- 「トランプ評価だけで結果が決まる」「沿岸は一律民主党」「大差の州は候補者個人が強い」と書き換えない。
- 個別候補者の影響度や2026年の当選確率を、この概説から計算しない。具体的な州の判断は既存の州調査と出典へつなぐ。
- 国全体の説明を8論点の各本文へ重複追加しない。パネル冒頭に必要な共通説明を置き、個別レポートは既存の公開状態に従う。

根拠は本文直後に小さな「概説の出典」として集約する。大統領評価と経済論点は[Pewの2026年7月調査](https://www.pewresearch.org/politics/2026/07/23/as-the-2026-midterms-approach-economy-is-front-and-center/)、都市・郊外・地方の説明は[Pewの2024年党派分析](https://www.pewresearch.org/politics/2024/04/09/partisanship-in-rural-suburban-and-urban-communities/)、投票参加は[Pewの2018〜2022年分析](https://www.pewresearch.org/politics/2023/07/12/voter-turnout-2018-2022/)に対応する。地域・候補者の比較に関する部分は、これらの全国分析と既存の州調査を読むための編集上の説明であり、特定州の因果効果を新たに認定するものではない。

### 3.5 地図への誘導

地図で州の情勢・候補者・争点を確認し、当選者や会派を選ぶと、上院の議席配分がどう変わるか試せる。

主なリンクを「地図で州を選ぶ」、補助リンクを「8つの論点を詳しく読む」とする。候補者選択と上院の機能を中心に説明し、未実装の「論点を指定すると候補者や勝率を自動予測する機能」が使えるようには書かない。

### 3.6 展開欄に残す制度の詳細

| 項目 | 掲載内容 |
|---|---|
| 上院のClass制度 | 任期6年、Class I・II・IIIに分かれ、2年ごとに一つを改選する。各州の2議席は異なるClassに属する、という一般説明。2026年の数字はここで繰り返さない |
| 今回の通常選挙・特別選挙 | Class IIの通常33議席に加え、フロリダとオハイオで特別選挙を行うことを説明 |

## 4. 横棒グラフの仕様

### 4.1 共通原則

グラフが答える問いは「全体のうち、今回どこが選挙の対象か」「目標までにどの部分を獲得する必要があるか」である。

- 各院で全幅を100%とし、分母を明示する。上院100議席と下院435議席を同じ全幅にしても、絶対数が等しいことを意味しない。
- 幅は常に `count / total * 100`。区分の合計は分母と一致させる。負数や合計不一致を黙って正規化しない。
- 非改選と改選の濃淡を維持する。淡色背景には濃い文字、濃色背景には十分なコントラストの文字を使う。
- 数字・党派・改選区分はタップやホバーをしなくても読めるようにする。小区分は図の直下に同じ値を表示する。
- 小区分を見せるための最小幅指定で割合を歪めない。色の凡例だけに意味を預けず、「非改選」「今回改選」「必要」の文字を添える。
- 説明文を数字の再読み上げで埋めない。文章は意味・条件・出典に絞る。
- 通常表示する基準値に利用者のシナリオを混ぜない。仮定の変更は、シミュレーション内の結果だけへ反映する。

### 4.2 制度説明の2本

| 図 | 分母と内訳 | 見せ方 |
|---|---|---|
| 上院の改選範囲 | 全100、非改選65、今回改選35 | 中立色の淡色65＋濃色35。ここでは党派を表さない。「今回35 / 100」を表示 |
| 下院の改選範囲 | 全435、非改選0、今回改選435 | 全幅を同じ中立色の濃色にする。「全435議席を改選」。非改選の区間は描かない |

党派を扱わないこの2本では、非改選65を理由なく左右に分割しない。中央に改選部分を置く仕様は、以下の党派別の上院図に適用する。中立色は既存の落ち着いた配色に合わせ、民主・共和の色と混同しないものにする。

### 4.3 全国要約の「投票前の議席」

ここに記す数字は、設計対象の同梱データの値であり、作成日に現職構成を再調査して更新した値ではない。画面は必ず基準データから生成する。

| 図 | 左からの区分 | 併記 |
|---|---|---|
| 上院 | 非改選・民主党会派34／改選・民主党会派13／改選・共和党会派22／非改選・共和党会派31 | 上院100、民主党会派47、共和党会派53。中央の35を今回の対象として明示 |
| 下院 | 民主党214／独立1／空席2／共和党218 | 下院435、全議席改選。独立と空席は別ラベル |

上院は淡青・濃青・濃赤・淡赤の順にし、中央の改選部分をひとまとまりとして認識できるよう、区間の上下に「今回改選35」を添える。その他会派・未確認・空席があるデータでも合計から省かない。

下院は全て改選対象なので、現職の議席を淡色の「非改選」に見せない。独立・空席は細くても図外に人数を残す。上院の党派は `Seat.caucus` に基づき、無所属を党籍から自動算入しない。

| 共和党会派が上院51 | 非改選31＋今回20 | 淡青34／中立・残り15／濃赤・必要20／淡赤31 |
| 下院の多数派の目安 | 全435中218。現状の民主党214からは純増4 | 中立の強調色・必要218／中立・残り217。全区間が今回改選 |

上院では対象会派の非改選と必要獲得分を連続させる。民主党の51の境界は左から51%、共和党は右から51%、すなわち左から49%の位置に置く。どちらにも無条件で中央50%の線を引く実装は避ける。下院は218/435、約50.1%の位置に目安を置く。

中立の「残り」は配分を指定していない区間であり、反対党の当選予測やToss Upの数ではない。ラベルは「残り18」「残り15」等とし、必要なら図外に「残りの配分は指定していない」と1回説明する。

共和党会派については、図のすぐ下に「19 / 35なら計50。共和党の副大統領による同数時の決裁票を前提とする」と短く添える。これは上院議員の過半数51と同一の条件ではない。副大統領の所属と確認状態は既存データを参照し、未確認なら所属を推測しない。[米上院による副大統領の説明](https://www.senate.gov/about/officers-staff/vice-president.htm)

下院の純増4は「共和党から必ず4奪う」という意味ではない。独立議員・空席がある現在構成との比較である。218は435議席を前提とする議席数の目安であり、全ての実際の採決や議長選に一律218票が必要だとは表示しない。

### 4.5 データと関数の契約

- 全体：上院は `seats.length`、下院は `houseSnapshot.total`。
- 上院の改選対象：`uniqueElectionSeatIds(elections)`。州名や選挙レコード数だけで数えない。
- 非改選：その集合に属さない `seats`。会派別には `currentCaucusCounts()` を再利用。
- 現在構成：`seats` と `houseSnapshot`。候補者を選択しても変更しない。
- 必要獲得数：目標議席数から対象会派の非改選数を引く。0未満は0。対象改選数を超えれば「今回の選挙だけでは届かない」とし、100%を超える棒は描かない。
- 前提データに会派未確認があって確定した必要数を出せないときは、そのケースを要確認とする。架空の配分を補わない。
- `seatBarMarkup` 相当の部品に `total`、区分、図の意味、任意の目標位置を渡す。既存の100議席グラフを呼ぶ箇所も、明示的に `total:100` を渡す。
- 目標位置には、左から数えるか右から数えるかを保持する。数値と位置を別々にハードコードしない。
- 部品にシナリオ状態の読込みを埋め込まない。現在・必要・仮定の各呼出側が値と表示名を渡す。
- 現行の `Math.max` による差分算出を流用する場合も、異常値を切り捨てて合計を見かけ上成立させない。

## 5. 開閉、移動、保存

### 5.1 概説の開閉

`#overview` 内に `details#intro-disclosure` を設ける。タイトルのsummaryは閉じた状態でも残す。ネイティブの開閉・キーボード操作を優先する。

保存キー案：`us-midterms-2026:intro-disclosure:v1`。値は `open` または `closed`。

| 状態 | 挙動 |
|---|---|
| 初回・保存なし・不正値 | 概説を展開し、6文も通常表示 |
| 保存値closed | 概説のみ閉じる。目的の1文と全国要約は表示 |
| 保存値open | 展開を維持 |
| 利用者がタイトルを開閉 | その状態を保存 |
| 保存領域が使えない | 初回は展開。その閲覧中は開閉できる。導入の保存失敗だけで大きいエラーを出さない |
| 図・地図・シナリオを操作 | 導入の状態に影響させない |

初めて見たというだけで、次回から勝手に閉じない。利用者が選んだ状態を保持する。内容更新のたびに強制展開もしない。Class等の小さな展開欄まで保存する機能は今回追加しない。

### 5.2 ページ内リンク

- `#overview` を概説として残す。旧リンクが来た場合は概説へ移動できるようにする。
- 概説内の「議席と権限」では、閉じた `#power-disclosure` を開いてから `#powers` へ移動する。
- 地図へのリンクは `#simulator`、図を読む位置は `#map-heading` と対応させ、移動時に地図見出しを確認できるようにする。
- `#issues` は引き続き「8つの論点」パネルへ接続する。旧ガイドの削除と同時に論点の入口まで消さない。
- リンクで一時的に開くために、利用者の導入開閉の保存値を書き換えない。手動開閉とリンクによる表示を区別する。
- 閉じる操作でフォーカスが非表示領域に残らない。論点・ニュースを閉じると、対応する入口とスクロール位置へ戻る。
- アンカーへの移動で既存の `?s=` を消さない。ブラウザの戻る操作と共有URLの復元を壊さない。
- 自動スクロールは移動先の準備後に行い、`prefers-reduced-motion` に従う。

### 5.3 既存保存との分離

`POWER_DISCLOSURE_KEY`、`DRAFT_STORAGE_KEY`、`SAVED_STORAGE_KEY`、シナリオの `schemaVersion` と `baselineVersion` を、導入の変更だけを理由に変えない。`SCENARIO_BASELINE_VERSION` は現行の選挙データの意味が変わらなければ維持する。サイトの表示版・編集日を更新しても、調査日・評価日・現職確認日を一括で新しい日付に置換しない。

## 6. 地図・シミュレーション付近の説明

## 7. 画面幅と可読性

- スマホは1列。冒頭のタイトルは目安28〜36px、本文は16px、補助の数字・出典は14px程度を基本とし、本文を縮小して一画面へ収めない。
- iPad縦も無理に制度説明と争点を横並びにしない。文章の読み順はすべての画面幅で一致させる。
- 上下院の棒は同じ幅で上下に並べる。院名と総議席数を図の見出しに付け、同じ全幅の意味を明らかにする。
- 全国要約は、広い画面では現在構成・必要配分の2列を主とし、その下に注目州・更新を置く。4カードを同じ細さで横並びにする現行構成を避ける。狭い画面では順に1列へ。
- 画面幅の切替目安は既存の800px・1100pxを使い、実測して調整する。横棒自体にページ全体の横スクロールを要求しない。
- 棒の中で数字が収まらないときは図外へ移す。色・説明・数値の対応を残す。ホバー用titleだけでは完了としない。
- 導入のボタン・summary・リンクは44px程度の操作領域を確保する。ブラウザ拡大、キーボード、スクリーンリーダーで到達できること。
- 図はfigureと説明、または同等の構造で意味を持たせる。読み上げには総数・改選区分・値を含める。図の `role=img` の中へ操作ボタンを入れない。
- 本文は通常のページスクロールで読む。導入専用の固定高スクロール欄を作らない。既存の全体・ニュース・ポップアップのスクロール仕様を保つ。

## 10. 今回の対象外と引継ぎ

- 新しい候補者・世論調査・ニュースの一斉更新。

- Xの収集・話題抽出・勝率推定。
- 論点の組合せから投票や候補者の当選確率を自動推定する因果モデル。

実装開始を妨げる未確定事項はない。本文の長さ、色の細かな調整、余白はこの設計の意味と可読性を守る範囲で担当者が調整する。研究上の結論や保存データの意味を変更する場合は、画面調整と区別して扱う。
