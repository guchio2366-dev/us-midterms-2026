# 接戦州の定点観測・更新手順

本書は `guchio2366-dev/us-midterms-2026` の定期調査担当用。承認済みの範囲は [設計書](design.md)。画面の内容は `src/data/observation.json`、候補者・議席・評価は既存の各データを参照する。情報源の原文を確認した担当が編集する。

## 実行と対象

毎日 09:00 Asia/Tokyo に確認を開始。月曜は候補者比較の全項目・反証を再点検する。開始時刻は公開完了時刻ではない。定期起動は ChatGPT の予約タスク、公開は既存の GitHub Actions / Pages が担当する。予約タスクの管理情報は `schedule.json`、ソース別の状況は `observation.json.sources` に記録する。

初回は6州の原文照合を手動実行した。`runs/initial-20260913.json` に確認範囲を残す。未完了の登録先は次回に優先する。定期タスクが予約されたことと、予約タスクが初回実行を完了したことを区別する。

対象は AK / ME / MI / OH特別 / TX / NH に加え、既存統合評価で新たに Toss Up となった選挙。評価変更で重点対象から外れた州の解説は削除しない。新たな対象の詳説が整うまでは既存の選択機能と「詳説準備中」を維持する。

## 毎回の調査

1. 最新 main を取得し、未公開の変更・並行作業を確認する。前回の記録と現在の `observation.json` を読む。
2. 情報源台帳を読み、`daily` の登録先と前回未確認の先を確認する。月曜は `weekly` も確認する。候補者公式サイトのニュース・予定欄も探す。固定記事だけを再読して「新規情報なし」にしない。
3. 選挙当局の名簿、Sabato / Inside Elections、世論調査の公表元、州内取材、大統領・政府・統計主体・討論会主催者を検索する。既存の `research-sources.ts` / `research-focus-sources.ts` は追加の検索先として使う。登録先以外の新規資料も必要に応じて確認する。
4. 最新の原文を開き、日付、対象、候補者名、根拠となる箇所を照合する。検索抜粋だけで新しい主張を公開しない。前回の文言や会話を未検証のまま転記しない。
5. 調査は実施期間・対象・標本数・方法・依頼主・質問を記録し、支持率と勝率、全体と部分標本、順位投票の第1希望と再配分後を分ける。異なる調査の数値差をそのまま支持変化と呼ばない。
6. 人物の政策・実績と有権者の評価を区別する。政策への賛成から投票や当選へ直結させない。疑惑を掲載する場合は正式な手続・判断の日付と重要な反論・訂正を同じ項目に含める。
7. 予定日を過ぎた項目は実施・延期・中止を原文で確認する。終了予定時刻を過ぎただけで実施確認にしない。調査公表日やTrumpの将来の発言を推測して日程を作らない。
8. 結果が確認できた予定には更新記事を追加し、`event.resultUpdateId` と `update.eventId` を相互参照する。延期時は旧日程を `dateHistory` に残し、新日程未定なら `date=null,time=null,status=postponed`。新日程確認後は `scheduled` へ戻す。関連する既存ニュースがあれば `newsId` を接続し、二重記事を作らない。

全国情勢では、既存ニュースと分析更新を「最近のニュース」、公開済みイベントを「今後の予定」に表示する。更新とニュースを統合するのは `update.newsId` で同じ出来事だと明示した場合だけとし、見出し・日付・根拠資料が似ているだけでは統合しない。イベントには実施状態とは別に `publicationStatus` を設定し、`published` のみ公開する。複数州に関係するイベントは一つの `eventId` を維持し、州ごとに複製しない。

情報源の代替先は同じ主張を裏付ける資料がある場合だけ用いる。世論調査そのものを取得できなければ、別調査をその調査の確認済み記録に代用しない。会員記事・接続失敗は部分確認として記録し、最後に確認できた本文を維持する。

## 編集・保存の規則

- `electionId` と `candidateId` は既存名簿を唯一の基準にする。同姓の AK Dan S. Sullivan と Daniel J. Sullivan Jr.、NH John E. Sununu と Chris Sununu を混同しない。
- `races` は公開状態 `published` のみ表示。入口の材料は最大2件、詳説は共通の5項目。本文・根拠が未確認なら下書きに留める。`reviewed` を公開状態として扱わない。
- `featuredSummary` と `lead` は短くし、候補者の順位付けや推定勝率を追加しない。注目州の順番は情勢分類と州英語名で固定する。
- 人物・予定の情報源を登録し、既存 `EvidenceRef` 形式の `sourceId / locator / checkedAt / kind` につなぐ。書き換えた主張には根拠を対応付ける。原文の長文転載を避け、要約する。
- 全米イベントは一つの `eventId` に州ごとの意味を関連付ける。日付だけ確認できる予定に時刻を設定しない。時刻ありの場合は IANA timezone を保持する。
- `revision` は公開内容の版。`races[].updatedAt` は本文が変わった場合のみ進める。確認だけで更新日を進めない。
- ニュース・分析の変更で `scenario/*`、保存案、共有URL、既存の議席基準を変更しない。`s` は共有された保存案、`race / observation` は読む位置だけを表す。
- 評価の原資料の変更が確認できたときのみ、既存評価スナップショットの方式を維持して更新する。記事から地図色を決めない。保存済み基準を最新評価に上書きしない。

## 確認記録

各実行の記録を `docs/observation/runs/<runId>.json` に残す。`startedAt` と `completedAt` は実際の処理時刻。記録を公開するコミットとその Pages workflow が公開結果の正本となる。

- 原文照合できた source のみ `checkedSourceIds` とする。取得だけ成功し内容未照合なら `reviewing`。
- 一部未確認は `partial`。全体失敗は `failed`。未確認を「重要な変更なし」にしない。
- 必須の範囲を照合し変更がない場合だけ `unchanged`。本文が変われば `changed`。
- `sources[].lastSuccessAt` と `contentVerifiedAt` はその source の照合が成功したときだけ進める。取得不能は `unavailable` とし、最後の成功日時を維持する。
- `monitor.lastCompletedAt` は照合を実行して完了した日次確認の時刻。部分確認はそのラベルも併記する。全体失敗・照合待ちでは前回値を維持する。36時間経過は表示時に検出する。
- ビルド・公開が失敗したら既存公開を維持し、実行結果に失敗と原因を残す。全体に接続できない場合でも最後の成功から36時間で遅延表示になる。

## 検証と公開

1. 最新 main から独立した作業ツリーで `npm ci`、`npm test`、`npm run build`。テストは参照整合性、公開状態、日時・確認状況と既存の保存・共有・逆算を確認する。
2. 予定や更新を追加しても全候補の選択・未配分・基準へのリセットが残ることを確認。初版の表示変更を伴わない日次データ更新では不要な画面テストを増やさない。
3. main が変わっていないか確認し、変わっていれば最新変更を取り込み再検証。force push はしない。検証したソースを1コミットで反映し、既存 Pages workflow の結果を確認する。dist の手編集はしない。
4. 公開された資産と本文を確認する。ユーザーに報告するのは重要な変化か調査・公開の失敗。変化なしの通知は繰り返さない。

2026年11月3日以降は開票結果・結果確定の確認を中心にし、未確定の選挙がなくなったら総括と予約タスクの停止を行う。将来の選挙や別分野へ監視範囲を自動拡張しない。
