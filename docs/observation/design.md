# 接戦州の判断支援・定点観測 設計書

作成日：2026年9月13日  
版：1.0／設計承認用  
対象：米国中間選挙2026サイトの上院接戦州解説・候補者比較・注目州・重要更新・今後の注目予定  
今回の成果物：設計書。サイトへの実装・公開、定期ジョブの起動は次工程である。

## 1. 目的と承認対象

**接戦州の判断材料を読み、自分の議席予想を置き、次の出来事を見て予想を更新できるサイトにする。** 初回は背景と候補者の違いを理解し、再訪時は新しく分かったことを短時間で確認する。勝敗を決められない州は未配分として残せる。

今回合意した方針は次のとおりである。

- 入口の情報を絞り、その下に候補者・争点・根拠の詳説を用意する。最大2つという制限は入口の判断材料に適用し、調査範囲には適用しない。
- 事実、有権者の評価、編集上の分析、未確認事項を区別する。材料から勝敗へのつながりを確認できない場合は、その限界を示す。
- 今後の出来事を「いつ・何があるか／この州との関係／何を確認するか」で示し、出来事の後は結果と判断材料の変化を追う。
- 注目州・州詳細・議席選択は同じ解説データを参照する。利用者の当選仮定とサイト側の情勢評価は別管理とする。
- ChatGPTへの質問、質問コピー、外部AIへの誘導機能は設けない。

本書で具体化した表示件数、文字数、更新時刻、鮮度基準、構成ファイル名は設計上の提案値である。本書の承認後、実装と表示確認を通じて意味を変えない範囲で調整する。

## 2. 範囲と既存機能との関係

初期の重点調査対象は、会話で合意したアラスカ、メーン、ミシガン、オハイオ、テキサス、ニューハンプシャーの6州である。この一覧は調査開始時の対象であり、永続的なToss Up判定や現在の勝率を意味しない。実装開始時に最新の候補者名簿、選挙ID、評価版を再確認する。

表示上の接戦対象は既存の統合評価から求める。評価更新により対象が増減した場合は件数も変わる。重点対象から外れた州も解説・更新履歴を削除せず、評価変更を記録して閲覧できるようにする。新しい接戦州は「詳説準備中」を明示し、既存の候補者選択は利用可能にする。

| 既存部分 | 本設計での対応 |
| --- | --- |
| 全国情勢の議席グラフ・地図 | 既存の統合評価を継続して使う。解説だけを根拠に色や暫定配分を変更しない。 |
| 注目州 | 州名・評価に、接戦の理由と判断の焦点を2文で追加する。 |
| 直近の重要な更新 | 何が起き、どの判断材料に関係するかが分かる要約と州詳細への入口を追加する。 |
| 州詳細・議席選択 | 現状、重要材料、注目予定、比較詳説を共通データから表示する。 |
| 保存案・共有URL・逆算 | 現行の議席状態と基準版を維持する。記事更新で保存案を再計算しない。 |
| 選挙を動かしうるニュース | 記事の入口として維持する。重要更新と同じ出来事はIDで結び付ける。 |

別作業の①冒頭への投票日追記、②主な論点の強調、③iPhoneニュース欄の表示件数・スクロール調整は本設計の変更対象外である。実装時は最新mainを取得し、これらを取り込んだ状態で作業する。

## 3. 利用者の行動

### 3.1 初回：全国情勢から判断材料へ

1. 全国情勢を見て、未配分の議席が多数派にどう関係するかを把握する。
2. 注目州の2文を読み、気になる州を開く。
3. 現状と最大2つの重要材料を読み、何が分かっているか、何が未確定かを確認する。
4. 判断できれば当選者を仮定する。詳しく知りたければ比較を開き、決められなければ未配分を維持する。

注目州から入っても、地図から入っても、未配分の議席から入っても、同じ選挙の同じ説明に到達する。

### 3.2 深く読む：候補者の評価を比較する

両候補について同じ項目を比較し、出典を必要に応じて開く。「自分が支持したい候補」と「州内で当選しそうな候補」を考え分けられるよう、有権者の評価や支持の広がりを確認できる場合は添える。比較をすべて読むことを議席選択の必須条件にはしない。

### 3.3 再訪：変化した部分から読む

全国情勢の重要更新、または州詳細の「直近の更新」への短いリンクから入り、結果・新しい根拠・残る不確実性を確認する。その後に保存済みの当選仮定を維持、変更、未配分に戻す。

初版では「直近の更新」を時系列で示す。「前回閲覧後の更新」や未読件数は、閲覧履歴を実装していない限り表示しない。既読管理や必須の判断理由入力は初版に設けない。

### 3.4 具体的な一連の利用例

以下は操作を説明する架空の例であり、実在する予定や支持動向ではない。

「州Aは現職への評価と政権への評価が焦点」と読む。候補者比較で判断がつかず、未配分のままにする。注目予定に討論会があるため、終了後に再訪する。更新欄で争点になった発言を確認するが、有権者の反応は未確認なので保留を続ける。後日の適切な調査で新しい判断材料が得られたら当選者を仮定し、議席数の変化を見る。討論会と調査結果の前後関係だけで因果関係を断定しない。

## 4. 情報構成とレイアウト

分析の中心は候補者比較、不確実性の説明、出来事の定点観測である。既存の地図・議席棒グラフを使い、追加部分は見出し付きの短文、比較表、日付付き一覧を基本とする。新しいチャート描画ライブラリは不要である。

### 4.1 全国情勢の注目州

各行を「州名・統合評価／接戦の理由と焦点の2文／分析の更新日」で構成する。要約は日本語80〜140字を目安とし、重要語を1〜2か所強調する。省略記号で核心を切らず、原稿を短く編集する。

並び順は既存の接戦優先・同分類内の州名英語順を維持する。ニュースが出たたびに州の位置を動かさない。新しい重要事項は別の更新欄で示す。全対象への入口を残し、スマホだけ一部の州が消える構成を避ける。

横画面の全国情勢3列は維持する。中央列の注目州は初期3件を表示し、「ほかの注目州を表示」で全件を展開する。初期3件は上記の安定した順序で選び、恣意的な有望州の選別をしない。狭い画面も同じ開閉操作とする。長文化による列高の増大を、文字縮小や新しい内側スクロールで解決しない。

### 4.2 州詳細の読む順序

| 順序 | 内容 | 初期表示 |
| --- | --- | --- |
| 1 | 州名・対象選挙・統合評価・現在の自分の仮定 | 常時表示 |
| 2 | 現状：なぜ接戦か、何が未確定か | 2文、120〜180字程度 |
| 3 | 重要な判断材料 | 最大2件。各100〜180字程度＋根拠への入口 |
| 4 | 今後の注目予定 | 日程付き最大3件。日程未定の観測項目は別に最大2件 |
| 5 | 当選者を仮定する | 全候補への選択経路と「未配分」を用意 |
| 6 | 候補者を詳しく比較する | 項目別に展開可能 |
| 7 | 直近の更新・過去の経緯 | 初期3件、続きを表示可能 |
| 8 | 調査・評価機関の原資料、出典、確認状況 | 必要に応じて展開 |

州詳細の上部に「直近の更新」「候補者比較」「当選者を選ぶ」への短い移動リンクを置く。再訪者や判断済みの利用者は、長い本文を再読せず目的の位置へ移れる。主要説明の直後から選べる経路を保つ。

### 4.3 iPad・iPhone

利用できる詳細領域が十分広い場合、現状と判断材料を左、注目予定を右に並べる。列幅は各320 CSS px以上を目安とする。iPad横画面でも州詳細パネル自体が狭ければ縦並びにする。端末名だけで2列を強制しない。

候補者比較は、広い領域では項目をそろえた左右比較、狭い領域では「経歴：候補A→候補B」「政策：候補A→候補B」の順に置く。候補Aの全項目を読んだ後に候補Bの全項目へ進む長い縦配置は避ける。

既存の州詳細の独立スクロールを維持し、その内部に複数のスクロール枠を追加しない。同じ州内の議席変更で読んでいる位置を失わせず、別の州への切替時は先頭へ戻す。更新リンクから入った場合は該当更新へ移動する。

党派色は候補・会派の識別に使う。未配分は中立色、選択中は枠と文字、更新状態は日付とラベルで示す。色だけで選択や確認状態を表さない。本文16px程度、操作領域44px程度を目安とし、タップ・キーボードで同じ情報へ到達できるようにする。

## 5. 調査と編集の基準

### 5.1 調査の順序

先に6州の資料を収集し、相反する材料も含めて整理した後で、入口の最大2つを選ぶ。州ごとの勝敗の分岐を先に決め、その説明に合う情報だけを集めない。

まず候補者名簿・選挙種別、調査原票・調査方法、評価機関の分類と日付を確認する。次に州内の主要争点、候補者の採決・政策・実績・発言、地元取材、有権者の評価、確認済みの今後の予定を集める。過去の会話にある候補者名、リンク、数値、予定は検証済み資料として無条件に転記しない。

### 5.2 入口へ採用する材料

「その材料を知ると、当選者の仮定を変えうるか」を編集上の基準とする。州との関係、根拠の直接性、現在の選挙への関連、反対方向の材料を確認する。

候補者の主張は「本人がそう述べた」根拠であり、政策の効果や有権者からの支持を証明するものではない。地域の産業構成や人口構成だけから、住民個人の支持先を推定しない。

各判断材料は「確認できた事実→当選見通しを考える際の意味→限界」を短くつなぐ。方向を説明できない材料は、その不確実性自体に判断上の意味がある場合に掲載する。材料が1つしか確認できない州では無理に2つ埋めない。

### 5.3 候補者比較

| 項目 | 調べる内容 | 表現上の条件 |
| --- | --- | --- |
| 経歴・地元との関係 | 職歴、活動、州との関係、支持基盤 | 生い立ちは政治姿勢や支持との関連を説明できる範囲で扱う。 |
| 政策・実績・発言 | 主要争点での公約、採決、行政実績、重要発言 | 公約、実施済みの行動、確認された効果を区別する。発言は日付と文脈を示す。 |
| 政党・大統領との関係 | 支持、対立、推薦、採決、共同活動 | 「親トランプ」「穏健」だけで済ませず、具体例を示す。 |
| 評価・批判・問題 | 評価される実績、批判、疑惑、審理や処分の状況 | 批判と確認された事実、疑惑と正式判断を区別し、重要な反論・訂正も扱う。 |
| 有権者の受け止め | 好感度、争点評価、党派を越える支持、投票参加 | 調査時点・対象・標本を確認し、未調査を支持なしと扱わない。 |

両候補の項目はそろえるが、証拠の量・強さを無理に均等化しない。未確認の場合は空白や「問題なし」で埋めず、確認状況を示す。第三候補・無所属が選択対象や勝敗理解に関係する場合は詳説への経路を残す。

### 5.4 世論調査・統合評価の扱い

得票意向、勝率、評価機関の分類を混同しない。「Toss Up（評価分裂を含む）」は勝率50%を意味しない。複数機関の元評価は日付付きで確認できるようにする。

調査は公表日だけでなく実施期間、対象、標本数、方法、依頼主、質問、未定層の扱いを記録する。異なる調査の数値差をそのまま支持変化と呼ばない。小さな部分標本や方法の違いがある場合は本文の解釈にも反映する。比較可能性が低い調査を一本の連続線にしない。

事実は通常の本文、解釈は「分析」、未検証の分岐は「仮説」として必要箇所に短く表示する。全文章に大量の注意ラベルを付けず、重要な不確実性は本文中で説明する。原資料の詳細は展開先に置く。

## 6. 今後の注目予定

### 6.1 掲載項目と採用条件

対象は討論会、候補者・大統領の訪問や演説、重要な政策発表・施行、経済指標、選挙手続の日程、公表予定が確認できた調査などである。存在や日付を推測して予定表を埋めない。

各項目は、名称、日付・時刻と精度、州との関係、確認する点、根拠、最終確認日を持つ。「何を話すか」「候補者がどう反応するか」「後の調査で何を確かめるか」まで書ける場合は具体化する。単なる大統領日程の転載はしない。

予定は原則として今後30日以内から、州への関連性を編集確認したものを日付順に初期3件表示する。それ以降の確認済み予定は「すべての予定」に置く。同日の並びは固定ID順とし、候補への期待で優先度を付けない。

全米共通イベントは1つの原データに複数選挙IDを関連付ける。州ごとの説明は分けられるが、日時や実施状態を複製しない。

### 6.2 予定と観測項目の区別

| 種別 | 表示 | 例となる状況 |
| --- | --- | --- |
| 日程確定 | 日付＋予定名 | 主催者等の公表を確認した討論会 |
| 発表済み・日付未定 | 日程未定＋予定名 | 実施自体は公表されているが日時がない |
| 継続観測 | 「次に確認したい点」に別掲 | 次の調査で無党派層の評価を確認したいが、公表予定は不明 |

将来の発言内容、政策決定、調査結果を予定上の事実として先取りしない。日付のみが分かる場合、架空の時刻を設定しない。米国の現地日付・タイムゾーンを保持し、時刻が確認できる予定のみ日本時間を併記する。

### 6.3 予定終了後の扱い

日付が過ぎたことだけで「実施済み」としない。表示上は「予定日経過・結果確認待ち」とし、実施、中止、延期のいずれかを根拠で確認する。延期は旧日程と新日程を履歴に残す。

実施を確認した後、「起きたこと／当初の注目点に対して分かったこと／なお未確認のこと」を重要更新へ登録する。元の予定と結果を相互参照し、未来の予定一覧から外す。発言だけ確認でき、投票行動への影響が不明なら、その状態を維持する。

## 7. 定点観測の運用

### 7.1 更新頻度の設計値

| 対象 | 確認頻度 | 作業内容 |
| --- | --- | --- |
| 重点州の新規調査・評価変更・主要ニュース・注目予定 | 毎日9:00 日本時間に開始 | 差分収集、原資料確認、必要箇所の更新 |
| 当日までに予定時刻を過ぎた出来事 | 毎日の確認時 | 実施・延期・中止と結果の確認。未確定なら保留 |
| 候補者比較・主要判断材料の全体見直し | 毎週月曜の定期確認に追加 | 古い説明、反証、候補者変更、新しい争点を点検 |

日次の開始時刻は公開完了時刻を保証しない。重大情報を定期確認以外で把握した場合は随時更新できる。初版は常時監視、リアルタイム通知、個別のプッシュ通知を約束しない。選挙後は結果確認と総括へ移り、選挙前の予定収集を惰性で継続しない。

### 7.2 情報源と確認範囲

各州について、選挙当局、主要候補者の公式情報、採用する評価機関、調査公表元、州内の継続取材媒体を情報源台帳へ登録する。全国イベントは大統領・政府・議会・統計公表主体・主催者の公式発表を優先する。候補者本人の主張に対する有権者評価は独立した資料で確認する。

台帳にはURL、対象選挙、情報の種類、取得方法、最終成功日時、確認頻度、取得不能時の代替先を持たせる。すべてのインターネット情報を網羅したとの表示はしない。「登録した情報源を確認した範囲」の状態として扱う。

### 7.3 更新処理

1. 登録情報源の差分と予定日経過を取得する。取得失敗を新規情報なしと扱わない。
2. 新しい情報を原資料と照合し、候補者・選挙・日付・主張の位置を記録する。
3. 重複を統合し、事実と分析を分けた更新案を作る。どの判断材料を変えるか、変えないかを明記する。
4. 更新担当が根拠・反証・日付・参照整合性を確認し、既存の公開ステータスを通して反映する。AIが担当する場合もこの照合を行う。
5. 検証済みのデータ版を公開し、確認結果と公開結果を記録する。失敗時は最後の正常版を維持する。

取得・型検証の成功だけで、政治的解釈の正しさを確認したことにはしない。自動収集した記事をそのまま主要判断材料として公開しない。出典を確認できない内容は下書きに留める。

### 7.4 確認状態の表示

| 内部の結果 | 利用者への表示 |
| --- | --- |
| 必須の登録情報源を確認し、重要な変更を反映 | 最終確認日＋分析更新日 |
| 必須の登録情報源を確認し、重要な変更なし | 「確認した範囲で重要な変更なし」＋最終確認日 |
| 一部の情報源を取得できない | 「一部の情報源を未確認」＋最後に確認できた日 |
| 未実行・全体失敗 | 最後の成功日時を維持し、確認の遅れを表示 |
| 取得できたが内容照合が未完了 | 「更新内容を確認中」。確認済みの本文を維持 |

日次確認の最後の完了から36時間を超えたら「確認が遅れています」を表示する。取得失敗等が判明した場合は36時間を待たず部分確認等を示す。分析を変更していない日に分析更新日を進めない。サイトを開いた時刻を最終確認日として表示しない。

### 7.5 実行基盤と完了条件

確認したリポジトリのGitHub Actionsは公開用で、日次の調査スケジュールは含まれていない。画面の追加だけでは定点観測は稼働しない。

実装時に、原資料の検索・閲覧、定期起動、差分保存、更新案作成、検証済みデータの反映を実行できる更新担当と実行環境を接続する。定期収集と解釈の照合は別工程として記録し、公開処理は既存のGitHub Pages経路を使用する。本文に外部取得や生成APIの資格情報を含めない。

日次ジョブは毎日9:00日本時間（UTC 00:00）を設計値とする。新しい外部サービス契約やAPIキーを当然の前提にせず、実装時に利用可能な実行環境を確認する。利用可能な仕組みが足りない場合は、調査済みの静的版として公開可能な状態まで完成させ、定期更新が未稼働であることと不足する接続を明記する。「自動更新中」と偽って完了扱いにしない。

定点観測の稼働完了には、初回の実行記録に加え、次の予約起動が存在することの確認が必要である。本書作成中には定期ジョブを作成・起動しない。

## 10. 状態・保存・性能

議席の選択は既存SenateChoiceを使用し、候補者指定、会派指定、未配分を混同しない。「未配分にする」は利用者の明示的な選択であり、「自動の初期配分へ戻す」と分ける。自動配分を利用者による固定指定に変えない。

ニュース、候補者解説、予定の更新だけでは保存案の基準版・議席を変更しない。候補者の撤退等でID対応が変わる場合は既存の再選択通知を使い、別人へ勝手に付け替えない。新しい接戦対象になっても保存済みの利用者指定は維持する。

共有URLの既存シミュレーション内容を保ち、州詳細や更新へ移動する参照IDは衝突しない任意パラメータとして追加する。参照先が存在しない場合は該当州の先頭、州も特定できなければ全国情勢へ戻し、議席仮定は保持する。共有された議席基準は保存時のもの、研究本文は閲覧時の公開版であることを更新日で区別する。

追加描画はDOM/CSSで所有する。初期画面は短い要約、選択中の州詳細は1インスタンス、候補者比較は開いた項目を中心に描画する。全州の長文を非表示DOMとして大量に置かない。大きな動画やSNS埋め込みは初版では使わず、公式原文へのリンクとする。

日次収集はサーバー側・定期実行環境で行い、利用者の端末からニュースサイトや生成APIへ一斉問い合わせしない。追加データが大きくなる場合は州単位の詳細読み込みに分け、入口要約を先に表示する。読み込み失敗時は確認済みの要約と既存の議席選択を維持し、再試行できるようにする。

初期導入による追加JavaScriptと要約データは圧縮後50KB以内を目安とする。数値は性能の合格保証ではなく、実装時の差分確認に使う予算である。既存地図を再生成せず、研究欄の開閉だけで地図の再描画を走らせない。

## 12. 受入条件

以下は実装時の確認項目である。本書作成時にテスト済みという意味ではない。

1. 注目州に接戦の理由と判断の焦点が2文で表示され、全対象への入口がある。
2. 地図・注目州・未配分の一覧から同じ選挙の判断支援へ到達できる。
3. 入口の判断材料は最大2つで、根拠不足のため1つの場合も成立する。
4. 詳説の調査範囲を入口の件数制限に合わせて削らない。
5. 公約・実績・効果、有権者評価、分析・仮説が混同されない。
6. 候補者比較は項目が対応し、第三候補等の選択経路が失われない。
7. 重要な人物情報には出典と日付が対応し、疑惑と正式判断を区別する。
8. 候補者の選択・変更・未配分への復帰が既存の議席集計へ反映される。
9. 未配分と初期配分へのリセットを区別し、自動配分を固定指定にしない。
10. 記事・予定・評価更新の際に、保存済みの仮定と共有URLの基準を勝手に変えない。
11. 未配分の対象が増減しても、件数・地図・入口が同じ統合評価に従う。
12. 日程確定、日程未定、継続観測を区別し、未確認の未来の日付を作らない。
13. 日付だけ判明した予定に架空の時刻や日本時間を付けない。
14. 予定日経過だけで実施済みにならず、結果確認待ちが成立する。
15. 実施・中止・延期を確認後、元の予定と結果を対応付けて追える。
16. 共通イベントの日付・状態が関連州で矛盾しない。
17. 更新日と最終確認日が異なる意味を持ち、変化なしと取得失敗を区別する。
18. 部分確認・照合待ち・確認遅延・公開失敗で、最後の正常な本文を維持する。
19. 定期ジョブが実際に予約され、初回実行・対象・確認結果・公開結果を追える。
20. 定期実行が未接続の場合は、未稼働であることを明示して完了範囲を限定する。
21. iPhone相当の390px幅とiPad相当の768px・1024px幅で横方向のはみ出しがない。200%文字拡大でも操作できる。
22. 州詳細内に多重スクロールが増えず、州切替と同州内更新のスクロール動作が区別される。
23. 保存・復元・共有・逆算の既存テストと追加の状態遷移確認が通り、入口から議席変更までを実画面で確認する。
24. ChatGPT質問機能、必須の判断理由入力、根拠のない勝率・争点からの自動配分が追加されていない。

設計の完成形は、短い入口、根拠のある比較、次に見る予定、確認状況がつながっていることである。定点観測の実装では、画面が表示できることと、調査・更新が継続して動くことの両方を確認する。
