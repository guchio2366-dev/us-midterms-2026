# 全国情勢の3列整理・ニュースと予定の統合 設計書

作成日：2026年9月13日

版：1.0／設計承認用

対象：米国中間選挙2026サイトの全国情勢・ニュース・接戦州の予定への導線

本書は実装のための設計である。この作成によってサイトのコード、公開内容、定期確認の設定は変更しない。

## 1. 目的と合意事項

iPad横画面の全国情勢を、左「議席情勢」、中央「注目州」、右「ニュース・今後の予定」の3列に整理する。「直近の重要な更新」は欄ごと撤去し、記事としての内容をニュースへ統合する。今後のイベントを追う機能も右列へ集約する。

利用者が左で全体の議席配分を把握し、中央で気になる州を選び、右で新しい判断材料や次に注目する予定を確認できることを目的とする。見出し・囲み・説明の重複を減らし、読み始める場所を明確にする。

今回の分析上の役割は「情勢の比較」と「出来事・予定の継続観測」である。既存の横棒グラフと通常のHTML一覧を使い、狭い画面では縦並びにする。

### 承認済み方針を具体化する設計判断

- 3列は原則として等幅とする。左列のグラフの見出しは棒の上に置き、数値に必要な幅を確保する。
- 右列には「ニュース・今後の予定」という見出しを一つ置き、その内部を「最近のニュース」「今後の予定」の2つの切替にする。初期表示は最近のニュースとする。
- 各切替は同じ一覧枠を使う。未来の予定と過去のニュースを一つの日付順に混在させない。
- 州詳細には判断材料と候補者比較を維持し、予定の一覧は関連する予定を右列で開く操作へ引き継ぐ。

## 3. 画面構成と情報量

### 3.1 iPad横画面

| 左：議席情勢 | 中央：注目州 | 右：ニュース・今後の予定 |
|---|---|---|
| 上院の暫定配分 | 接戦理由を示す州カード | 最近のニュース／今後の予定の切替 |
| 民主党・共和党の51議席への必要配分 | 初期3州、残りは「ほかの注目州」 | 選択した一覧を枠内スクロール |
| 共通凡例・短い注意書き | 地図で全選挙を見る | 一覧のページ操作 |
| 評価内訳・集計方法の折りたたみ |  | 最終確認・確認状況 |
| 下院の多数派の目安 |  |  |

`.national-grid` の直接の子を上記3つにする。`.national-middle` は撤去する。3列の上端、外枠、内側余白、列見出しの書体と大きさをそろえ、`align-items:start` で自然な高さにする。短い列を左列の高さまで引き延ばさない。

既存の横画面条件（幅944px以上・高さ600px以上・landscape）を出発点に、`repeat(3,minmax(0,1fr))`、列間16px、内側余白16pxで実装する。944px境界と1024px幅で数値の衝突がないことを確認する。幅が足りない場合はページ左右余白を先に調整し、それでも成立しない幅だけ1列へ切り替える。文字を縮小して3列を成立させない。

左列の長い集計説明は「集計方法・出典」内へまとめる。常時表示の注意は「2機関が一致した方向へ暫定配分。接戦・評価分裂は未配分。当選確率ではない」という意味を保つ。非改選・改選、D側・R側・未配分の区別と必要議席の数値は常時読める状態にする。

中央は現在の初期3州と残りの折りたたみを維持する。更新欄を除いた余白を埋めるために文章や表示件数を増やさない。州名、評価、短い論点見出し、説明、分析更新日をそろえる。Toss Up、Lean、同分類内の州英語名順という既存の掲載順を維持する。

### 3.2 右列の見た目

外側の枠は一つとし、切替、一覧、ページ操作、確認状況をこの中に配置する。記事ごとの強い囲みや太い色帯は簡素化し、余白と薄い区切り線で分ける。党派色は議席や情勢を表す既存の役割に限定する。予定の状態は文字で示し、色だけに依存しない。

一覧項目は「日付・対象」「見出し」「短い要約」の順とする。見出し16px以上、補足14px以上を基準とし、全体をタップ可能にする。長い要約は一覧用の短い文章を用意し、根拠・留保・詳説は記事内で読む。出典本文や複数の説明ラベルを一覧へ並べない。

既存の長いニュース導入は「最近の出来事と、次に注目する予定を確認する。」程度に縮める。調査対象・編集方針は詳細にまとめる。

### 3.3 iPad縦画面・iPhone

「議席情勢→注目州→ニュース・今後の予定」の1列とする。右列の2切替は同じ位置・名称で維持する。

iPhoneでは選択中の一覧が標準文字サイズで約3件見える高さを目安にし、枠内スクロールを維持する。高さは固定の3行ではなく、画面高と文章量に応じて上限を設ける。現在の `min(31rem,65svh)` を出発点に確認する。文字拡大時は見える件数が減ってよく、タイトルや操作を切り捨てない。

iPad横では一覧の上限を520px程度とし、短い一覧は内容の高さに収める。各切替は10件単位の既存ページ送りを再利用する。10件はページ単位であり、一度に画面へ露出させる件数ではない。

## 4. ニュースの統合と重複処理

### 4.1 一覧に含める内容

最近のニュースには、公開済みの既存ResearchNewsItemと公開済みのObservationUpdateを含める。独立した「更新情報」カテゴリや枠は作らない。

公開済みの分析更新は「何が起きたか」「判断材料がどう変わったか」「まだ何が分からないか」を記事として読める形にする。単なる作業ログ、確認しただけの記録、未公開の下書きはニュースにしない。既存の発言・政策・選挙・経済などの意味に応じた種類表示を使う。

### 4.2 同じ出来事を一つにする規則

1. ObservationUpdateに公開済みニュースへの `newsId` がある場合、そのニュースを代表記事として一件だけ表示する。分析更新の判断材料・留保・根拠は記事詳細に統合する。
2. `newsId` がない更新は独立した記事として表示する。初回移行では既存ニュースと内容を照合し、同じ出来事なら明示的に関連付ける。
3. 見出しや日付が似ているだけで自動削除しない。同じ調査でも調査対象・期間が違う場合は別の出来事である。
4. 一つの更新が複数州に関係しても全国一覧では一件にする。記事内で関係する各州の意味を示す。
5. 非公開のニュースを参照していても、その参照を理由に公開済み更新を消さない。公開可能な更新部分を独立表示し、非公開本文は露出させない。

既存IDを保存し、旧記事や更新へのリンクから統合後の代表記事へ到達できるようにする。本文を二つのデータへコピーして同期する方式は採らず、参照を集約して一つの詳細表示を生成する。

### 4.3 日付と詳細表示

一覧は出来事の日付の新しい順。同日の場合はサイト更新日、安定したIDの順で決める。発生日が未特定なら掲載日を並び替えに用い、表示には「掲載」と明記する。サイト更新日を出来事の日付として表示しない。

記事は既存のニュースモーダルで開く。発生日・調査期間・公表日・サイト更新日を区別し、事実、考えうる意味、不確かな点、根拠、関連する州への入口を表示する。分析更新には既存ニュースにしか存在しない地図や政策段階を無理に補わない。関連記事から州へ進み、戻ったときの一覧位置と記事内位置を復元する。

## 5. 今後の予定と結果への接続

### 5.1 対象

公開可能な根拠を確認した討論会、統計発表、候補者や大統領の訪問など、具体的なイベントを扱う。全米イベントは一つの `eventId` として掲載し、関係する州を記事内で列挙する。6州に関係しても6件に複製しない。

「生活費への受け止めを見る」「次の調査を確認する」など日程が発表されていない観察項目は予定に変換しない。これらの `watchItems` は州詳細の判断材料の近くに残す。発表済みイベントで日程だけ未定の場合は、その状態を明示して予定内に掲載できる。

### 5.2 表示順と状態

「今後の予定」の通常一覧は、日程確定の予定を近い順、その後に発表済み・日程未定を置く。30日を超える予定も同じ一覧で到達可能にする。ページを分けても欠落させない。

結果確認待ち・延期・中止・実施済みは同じ切替内の「結果確認・日程変更・過去の予定」にまとめ、既定では折りたたむ。確認待ちや変更がある場合は、その件数を見出しで分かるようにする。通常一覧が空でも、確認待ちや日程未定の情報があることを伝える。

| 状態 | 表示と処理 |
|---|---|
| 日程確定 | 現地の日付と、分かる場合のみ時刻を表示 |
| 発表済み・日程未定 | 日付を補わず、そのまま表示 |
| 予定日時を経過 | 「結果確認待ち」。時間経過だけで実施済みにしない |
| 延期 | 確認した旧日程と変更理由を詳細に残す。新日程不明なら未定 |
| 中止 | 根拠と確認日を保持し、通常の今後一覧から外す |
| 実施確認 | 元の予定を履歴として保持。結果記事があれば接続 |

時刻がある予定はIANAタイムゾーンと夏時間を用いて比較し、日本時間も併記する。日付だけの予定に日本時間や午前0時を付与しない。異なるタイムゾーンの同日予定で時刻まで比較できない場合は、現地日付と安定IDで並べ、厳密な時刻順であるかのように見せない。

### 5.3 予定の詳細と結果

予定をタップするとニュースと同じモーダルで「予定の内容→注目する理由→確認する点→関連州→出典」を読む。複数州に関係する予定では、全体の説明と州別の意味を区別する。

実施結果を原資料で確認したら最近のニュースに結果記事を載せ、既存の `resultUpdateId` と更新側の `eventId` を相互参照させる。予定から結果へ、結果から元の予定へ移動できるようにする。実施確認済みでも結果記事がまだなければ、その旨を示し、架空の記事リンクを作らない。

## 6. 州詳細・保存・共有・操作

州詳細の予定一覧は「この州の今後の予定を見る」というボタンへ置き換える。押すと右列の予定切替を開き、当該選挙に関係する予定だけを表示する。絞り込み中は州名と「すべての予定へ」を一行で示す。通常表示に常設のフィルター群は追加しない。州詳細の判断材料、候補者比較、観察項目、当選者の選択は維持する。

州詳細の更新・関連ニュースは共通の記事を開く入口とし、全国一覧と同じ記事解決規則を使う。全国の独立更新欄を撤去しても、州別の文脈と旧リンクを失わないようにする。

一覧の切替・ページ番号・スクロール位置は各切替ごとに保持する。記事の開閉や州からの帰還で元の位置へ戻す。予定の状態を再計算しても、閲覧中の一覧を勝手に並べ替えたりフォーカスを移動したりしない。並び替えは次に一覧を開いたときに反映する。

共有のため、既存の `s`（議席仮定）、`race`、`observation` に加え、次の任意パラメーターを定義する。

| パラメーター | 意味 |
|---|---|
| `newsTab=recent` / `upcoming` | 開く一覧。省略時はrecent |
| `newsItem=news:<id>` / `update:<id>` / `event:<id>` | 開く記事・予定。種類付きIDで衝突を防ぐ |
| `newsRace=<electionId>` | 州詳細から引き継ぐ対象選挙。省略時は全対象 |

有効なnewsItemを最優先で解決し、それに合う切替を開く。統合されたupdate IDは代表ニュースへ解決する。旧 `race`＋`observation` の更新・イベントIDも同じ記事へ解決し、比較・判断材料などの旧リンクは州詳細で維持する。無効なIDは該当する一覧へ戻し、非公開の内容を出さない。

一覧切替はreplaceState、記事を開く操作はpushStateを基本とし、戻る操作で一覧と元のスクロール位置へ復帰する。直接開いた記事の閉じる操作は、外部ページへ戻さず当該一覧を表示する。既存モーダルの履歴処理と二重に動作しないよう、一か所で管理する。閲覧状態の変更が議席仮定の `s` を変更・削除しないことを必須とする。

2切替は適切なtablist/tab/tabpanelとし、矢印キー、Enter/Space、フォーカス表示を備える。タップ領域は44px以上。モーダルは閉じる操作、Escape、フォーカスの復帰を維持する。200%文字拡大でも横にはみ出さず、枠内スクロールをキーボードで操作できるようにする。

## 7. データ・実装構成

データの正本は既存のニュースと `observation.json` を維持する。表示時の統合用に純粋関数 `buildNewsFeed()` を設け、出典や記事本文を重複保存せずに型付きの参照を返す。

統合項目は安定ID、種類、元データ参照、関連選挙ID、代表記事ID、並び替え用日付と日付の意味を持つ。news、update、eventを区別する共用型とし、項目が持たないメタデータを捏造しない。

現在のObservationEventには公開状態がないため、公開制御用の必須フィールド `publicationStatus` を加える。初回移行で既存イベントの根拠を照合し、公開する各レコードに明示的にpublishedを設定する。以後はpublishedだけを表示し、未指定・下書き・確認中は除外する。イベントの実施状態 `status` とは別に扱う。

| ファイル・機能 | 実装内容 |
|---|---|
| `src/main.ts` | 中央の更新欄・中間ラッパーを撤去。ニュース統合、切替、モーダル、復帰状態を接続 |
| `src/style.css` | 3列の等幅化、不要な旧ルール整理、一覧の簡素化、画面幅ごとの表示 |
| `src/news-feed.ts`（新設案） | 公開判定、代表記事解決、重複統合、日付順、州別抽出 |
| `src/observation-logic.ts` | イベント公開判定と全対象の予定一覧。既存の時刻・確認状態判定を再利用 |
| `src/ui/observation.ts` / CSS | 予定一覧から共通一覧への導線、観察項目、旧リンク解決 |
| `src/data/observation-model.ts` / JSON | イベント公開状態、必要な既存ニュースへの関連付け |
| 定点観測の手順書 | 更新記事の統合、予定の公開状態、結果リンクの記録方法を追記 |

表示の所有者は既存のTypeScriptとHTML/CSSとする。新しい描画ライブラリ、外部フィードAPI、常時通信を追加しない。ニュース一覧は一インスタンス、記事モーダルも既存の一つを再利用し、非表示の切替を含めた大量の記事本文の事前描画を避ける。1ページ最大10件を描画し、本文は開いたときに組み立てる。

## 8. 定点観測の継続

毎日9時（日本時間）の既存タスクと月曜の全面確認を継続する。今回の設計・実装のために別の定期タスクを作らない。

手順書に「新しい出来事はニュース一覧へ」「同一の出来事は既存記事へ関連付け」「予定結果は相互リンク」「未公開イベントは表示しない」を追記する。設定済みタスクの指示が撤去した更新欄を明示的に要求している場合のみ、同じタスクの指示を修正する。

右列末尾は最終確認日時を一行で示し、一部未確認・失敗・遅延のときは状態を併記する。詳しい確認範囲と予定は折りたたみに置く。成功していない確認を成功扱いにせず、確認日時と記事更新日時を分ける。状態更新でニュース本文や保存案を再生成しない。

## 9. 実装手順と受入条件

### 実装順

1. 最新mainを取得し、既存保存・共有・ニュース遷移の挙動と並行変更を確認する。
2. 統合用の純粋関数、イベント公開状態、既存記事との明示的な関連付けを実装する。
3. 共通一覧・記事詳細・予定詳細・結果リンクを接続する。
4. 3列構成へ変更し、独立更新欄と旧ラッパーを撤去する。
5. 州詳細からの導線、旧リンク、一覧位置・フォーカス復元、共有URLを接続する。
6. 定点観測の手順書を更新し、必要な範囲だけ既存タスクの指示を合わせる。
7. 既存テストと追加の意味あるテスト、本番ビルド、代表画面の操作確認を行う。実装を公開する際は検証済みソースを最新mainへ通常の早送りで反映し、Pagesの成功を確認する。

### 受入条件

| 番号 | 確認内容 |
|---|---|
| 1 | iPad横の1024×768、1180×820、1366×1024で3列が成立し、列上端がそろう |
| 2 | 全国情勢に「直近の重要な更新」の見出し・枠・空き領域が残らない |
| 3 | 左列の議席数・未配分・必要議席・非改選／改選の区別を縮小せず読める |
| 4 | 中央に注目州だけが並び、接戦6州と既存の他の注目州へ到達できる |
| 5 | 右列は一つの枠で、最近のニュース／今後の予定を切り替えられる |
| 6 | 既存の公開ニュースと公開更新が欠落せず、明示的に関連付けた出来事は一件になる |
| 7 | 見出しが似ていても別調査を誤って統合しない |
| 8 | 複数州に関係する更新と全米イベントが全国一覧で重複しない |
| 9 | 下書き・確認中・非公開・公開状態未指定のイベント本文を表示しない |
| 10 | 発生日・公表日・サイト更新日が混同されず、同日の掲載順も安定する |
| 11 | 時刻付き予定は夏時間を含め正しく扱い、日付だけの予定に時刻を付けない |
| 12 | 時間経過だけで実施済みにならず、結果確認待ち・延期・中止へアクセスできる |
| 13 | 予定と確認済みの結果記事を相互に開ける。記事未作成の場合も壊れたリンクがない |
| 14 | 州詳細から関連予定を開き、全対象へ戻せる。観察項目とイベントが混同されない |
| 15 | タブ切替・記事開閉・州からの帰還で、一覧ページとスクロール位置を復元する |
| 16 | 旧更新・イベントへの共有リンクと新しい記事リンクが有効で、無効IDは安全に一覧へ戻る |
| 17 | 議席仮定、初期基準、旧保存案、共有URLのs、未配分、逆算の挙動が維持される |
| 18 | 768×1024と820×1180では1列となり、390×844の標準文字サイズで一覧が約3件に収まる |
| 19 | 944px境界、横向きの小画面、200%文字拡大で横方向のはみ出しや操作の欠落がない |
| 20 | タッチ、キーボード、Escape、フォーカス復帰、枠内スクロールを操作できる |
| 21 | 確認状況が右列に残り、部分確認・失敗・遅延を隠さない |
| 22 | 既存の定期タスクを重複作成せず、更新データが統合後の一覧に反映される |
| 23 | 既存106件を基準とする回帰テストと、統合・公開状態・日時・遷移の追加テスト、本番ビルドが成功する |
| 24 | 公開時にPages成功と公開画面を確認する。画面サイズによるブラウザ確認と実機確認を区別して報告する |

重複統合、公開制御、旧リンク、保存・共有の保持を自動テストの重点とする。列の見やすさとタップの流れは代表画面で確認し、CSSの記述をそのままなぞるだけのテストは増やさない。

## 10. 完了時に利用者ができること

全国情勢を開くと、3列の役割が見出しだけで分かる。中央で州の争点をつかみ、右で最近の出来事を読み、今後の予定へ切り替えて「次に何を見ればよいか」を確認できる。予定の結果が判明したら同じ欄で結果を追い、必要に応じて州詳細へ戻って自分の議席仮定を見直せる。
