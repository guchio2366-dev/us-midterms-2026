## 1. 完成形と対象範囲

### 1.1 利用者ができること

冒頭では、現在の党派別議席と今回の改選範囲を一度に把握する。全国情勢では、情勢評価に基づく暫定配分と、両党がそれぞれ51議席を確保するための配分を、同じ尺度の3本の棒で比較する。iPad横画面では制度と論点を左右で読み、州地図を表示した後は、地図を見ながら右欄の解説を読み進められる。

| 要望 | 採用する仕様 | 詳細 |
|---|---|---|
| ① 現在の議席を残す | 冒頭の上下院の棒に現在の党派構成を表示。上院は改選・非改選を濃淡で区別 | 3章 |
| ② 情勢と両党の目標を比較 | 横棒を縦に3本配置。党派の左右、全幅、非改選の位置、凡例を共通化 | 4・5章 |
| ③ 長い出典を閉じておく | 制度説明パネル内の「出典・確認日」を初期状態で閉じる | 6章 |
| ④ 主な論点から8論点へ | 主な論点の末尾へ既存の入口を移動。閉じた後に読書位置を復元 | 2・6章 |
| ⑤ 8論点は現状維持 | 8論点の本文、分類、公開状態、個別資料は編集対象外 | 1・10章 |
| ⑥ iPad横画面の導入 | 左に制度、右に主な論点。Class・特別選挙は両列を横断するポップアップ | 2・6章 |
| ⑦ 地図と州解説の高さ | 地図と右欄を表示可能な高さに収め、右欄本文を枠内でスクロール | 7章 |

全国情勢・ニュース・議席と権限などのページ内ナビゲーションの配置変更は、今回の表示改善後に別途判断する。ニュース一覧や権限表の全面改修、下院の新しい予測統合、論点から勝率を算出する機能、シナリオの初期値変更は今回追加しない。

### 1.2 実装の前提

既存のTypeScript・Vite・HTML/CSS・SVG地図を使用する。棒は少数区分の横積み棒であり、既存のHTML/CSS部品を拡張する。グラフライブラリ、バックエンド、閲覧時の外部API呼び出しは追加しない。情勢評価は出典を確認した静的スナップショットとして同梱する。

## 2. 冒頭のレイアウトと原稿

### 2.1 表示順序

サイト名と目的の一文を常時表示し、その下の概説は初回に開く。利用者が手動で閉じた状態は、既存の保存キーで保持する。

| 表示領域 | iPad横画面・十分な幅のPC | iPhone・iPad縦画面・狭いウィンドウ |
|---|---|---|
| 概説のタイトルと開閉 | 2列全体の上に配置 | 全幅に配置 |
| 制度の概説 | 左列。制度説明、上院の棒、下院の棒、効用、権限へのリンク、制度詳細ボタン | 先に表示 |
| 選挙を見る主な論点 | 右列。6文の本文、簡潔な出典、8論点への入口 | 制度説明の次に表示 |
| このサイトでできること | 両列の下を横断。機能説明と「地図で州を選ぶ」 | 論点の次に表示 |

導入の2列化は、CSS上の表示幅960px以上かつ横長の表示領域を基準にする。端末名やUser Agentでは判定しない。基本比率は1対1、列間は24〜32px。左列内の上下院の棒は縦に並べる。iPad縦画面、分割表示、文字拡大で幅が不足した場合は1列へ戻す。

本文は原則16px、補足は14px、行間は1.75〜1.85とする。左右の領域は同じ行で外枠の高さを揃え、下端の制度詳細ボタンと8論点の入口を揃える。左右の本文に同じ行数や固定高さを強制しない。省略表示、内部スクロール、空段落による高さ調整を導入部分へ追加しない。

### 2.2 主な論点の原稿

初期実装では既存の6文を保持する。新しい配置を実測し、説明不足が残る場合だけ既存資料に基づく具体例を最大2文追加する。高さ合わせだけを理由とした追記は行わない。

> 今回の中間選挙では、トランプ政権の運営や政策への評価が、全国の選挙情勢を左右する大きな要因となる。都市部では民主党、地方部では共和党の支持が強い傾向があり、郊外では支持が分かれている。物価や雇用、移民、医療などは複数の州に共通する論点で、同じ政策でも地域の産業や暮らしによって受け止め方が異なる。
>
> 候補者の実績や政策姿勢、地元との関係によって、全国的な党派の傾向と異なる結果になる場合もある。支持する相手が変わることに加え、どの支持層が実際に投票に行くかも結果を左右する。全国の傾向と各州の事情を併せて読むことで、接戦の理由や議席が動く条件を考えやすくなる。

本文直後に短い「概説の出典」を置く。常時表示する出典ラベルは「大統領評価・経済」「都市・郊外・地方」「投票参加」のように短縮し、対応する既存資料へリンクする。長い資料名・URLを列内に並べて左右の高さを崩さない。

右列の末尾に「各論点の地域差や根拠を、8つの論点で詳しく読む。」と添え、「8つの論点を詳しく読む」ボタンを置く。既存のopen-issuesをこの位置へ移し、同じIDを複製しない。既存の8論点パネルを開く動作と、#issuesからの直接表示は維持する。

下段の機能説明は既存の一文を使う。「地図で州を選ぶ」は地図の見出しまで移動する。既存の#simulatorや#map-headingの直接リンクは壊さず、実際の描画後のDOMで到着位置を確認する。

## 4. 全国情勢の3本比較

### 4.1 一つの比較領域へ統合する

現在の「投票前の議席」は3章の冒頭へ集約する。全国要約の主な領域には、上院の暫定配分と両党の必要配分をまとめる。別カード間で上下院を行き来する配置を解消する。

見出し：「上院の情勢と、51議席までに必要な配分」

| 行 | ラベル | 表示するもの |
|---|---|---|
| 1 | 情勢評価に基づく暫定配分 | 非改選＋複数機関の評価を集計した改選議席。接戦は未配分 |
| 2 | 民主党会派が51議席を確保 | 非改選＋今回獲得が必要な議席＋配分未指定の残り |
| 3 | 共和党会派が51議席を確保 | 非改選＋配分未指定の残り＋今回獲得が必要な議席 |

3本は縦に並べ、棒の開始位置・終了位置・幅を一致させる。右揃えの合計ラベルが棒の幅を変えないよう、共通グリッドで揃える。狭い画面では行ラベルを各棒の上へ置く。3本を横3列にはしない。

非改選のラベル、色の凡例、「今回改選35」の範囲表示、資料・方法への入口は比較領域全体で共用する。各行の数値は省略しない。3本それぞれに同一の長い説明を繰り返さない。

### 4.2 区間の順序と計算

現在の同梱データでは、全3本で左端34議席と右端31議席が非改選となり、左から34〜69議席の範囲が今回の改選対象となる。

| 行 | 左からの構成 | 到達点 |
|---|---|---|
| 暫定配分 | 淡青・非改選D／濃青・D側優勢／グレー・接戦や評価分裂／別柄・評価不足等／濃赤・R側優勢／淡赤・非改選R | 特定の勝敗を確定しない |
| 民主党51 | 淡青34／濃青・必要17／白地・未指定18／淡赤31 | 左端から51議席の位置 |
| 共和党51 | 淡青34／白地・未指定15／濃赤・必要20／淡赤31 | 右端から51議席、左端から49議席の位置 |

目標議席数は原則として全議席数の半数を超える整数。今回必要な獲得数は「目標−対象会派の非改選議席数」で計算する。共和党の目標線を民主党と同じ左から51%へ置かない。非改選の構成が変わった場合も、既存のsenateBreakdownとsenateMajorityPathから計算する。

トスアップの幅は該当する議席数に比例させる。グレー部分を画面中央へ強制的に中央揃えせず、両党の優勢議席の間に実数どおり配置する。多数派の目標線は各目標行だけに置き、「51」を棒外へ表示する。

目標行の白地は「残りの配分は指定していない」の意味であり、トスアップや相手党の勝利予測ではない。区別が分かるよう白地に細い枠を付ける。評価不足の柄は白地の未指定とは別にする。

### 4.3 優勢の内訳と注記

全国比較ではSolid・Likely・Leanを同じ濃い党派色でまとめる。Inside ElectionsのTiltも、5章の規則に従い方向のある評価として集計し、元の分類は保持する。「確定」「安全議席」とは表示しない。

棒の近くにD側・R側・接戦それぞれの数値と「内訳を見る」操作を置く。内訳は比較領域内の展開欄とし、同時に一つを表示する。対象州、通常／特別、各機関の元評価、確認日、出典を表で確認できるようにする。合成したSolid等の分類を新たに捏造しない。小さい棒部分をタップできなくても、独立した44px以上のボタンから同じ情報へ進めるようにする。

共通説明は以下を基本とする。

> 複数機関の最新の情勢評価を機械的に集計した暫定配分である。接戦は未配分とし、当選確率や最終結果を示すものではない。下の2本は51議席を確保するための配分例である。

50対50については既存の副大統領データから短い補足を生成する。共和党所属を確認できる場合の例は「共和党は今回19議席で計50。50対50では副大統領の決裁票が関係する」。51議席を確保する目標と、同数時の運営条件を同一視しない。詳しい採決条件は既存の「議席と権限」へつなぐ。

### 4.4 下院・周辺情報

下院の現在構成は冒頭に残し、全国要約には全435議席を前提とする218議席の目安を、既存の横棒でコンパクトに残す。下院の棒を上院の3本の間へ挟まない。下院について新しい複数機関統合は本書の対象外である。

注目州と直近の重要な更新は比較図の下に置き、十分な幅では2列、狭い幅では1列とする。既存の抽出件数・選定方法は維持し、全国比較の集計に合わせた独自ランキングは追加しない。

## 5. 情勢評価の集計方法

### 5.1 何を統合するか

統合対象は、Cook Political Report、Sabato's Crystal Ball、Inside Electionsの選挙別情勢評価とする。世論調査の得票率、調査人数、予測市場の価格、利用者の仮定はこの計算へ入力しない。全国世論調査から州別議席へ配分することもしない。

現行の地図はSabatoの分類を採用し、州別資料には一部選挙の評価比較がある。これだけで「全35選挙を複数機関で集計済み」とは扱えない。実装時の必要作業として、通常33・特別2の各選挙について、最低2機関、可能なら3機関の現行評価を一次資料で確認する。

地図の色は当面、既存の採用機関による分類を維持する。全国比較には「複数機関の集計」、地図には採用機関名と評価日を明記し、評価方法が異なることを内訳欄にも説明する。全国比較の集計値で、地図・シナリオ・候補者の初期選択を無断で置き換えない。

### 5.2 観測値と出典の条件

既存のRatingObservationは履歴を含むため、単純に全件を数えない。新しいスナップショットでは、次の項目を持つ評価観測を使用する。既存の履歴レコードへの参照・変換で再利用してよいが、資料の年月日を推測で補完しない。

| 項目 | 型・意味 |
|---|---|
| snapshotId / methodVersion | 公開した評価データの版／集計規則の版。methodVersionの初期値はdirection-majority-v1 |
| snapshotAsOf | この集計が対象とする確認基準日 |
| observationId / electionId / seatId | 観測、選挙、議席の識別子。1選挙につき1議席を数える |
| organizationId | cook / sabato / inside。表記揺れを正規化し、同一機関を重複計数しない |
| ratingRaw / category | 原資料の表記と、Solid・Likely・Lean・TiltのD/R、Toss Up、その他、未確認の分類 |
| ratedAt | 原資料が評価時点を明示している場合の日付。日付不明はnull |
| currentConfirmedAt / retrievedAt | 現行評価であると確認した日／資料を取得した日。ratedAtとは別の意味 |
| sourceIds / evidenceIds | 原資料と該当箇所。既存の出典・根拠形式を再利用 |
| status | publishedのみ集計対象。draft・withdrawn等は除外 |

過去の記事を最近取得しただけでは、現行評価の確認にならない。機関の現行表、対象選挙ページ、または基準日を裏付ける保存資料で確認する。評価変更日が古くても現行表で継続を確認できれば採用できる。ratedAtが不明な資料を取得日で埋めない。

同一機関・同一選挙の複数レコードは、現行として確認した1件を選択してから集計する。旧評価と新評価の2票化を禁止する。現行レコードを一意に決められない場合はその機関の当該選挙を除外し、内訳に理由を残す。

### 5.3 決定規則

これは分析機関の方向判断を整理する表示上の規則であり、独立した勝率モデルではない。機関ごとの重みは等しくする。

1. 各機関のSolid D・Likely D・Lean D・Tilt DをD方向、Rの各分類をR方向、Toss UpをT方向として扱う。Safeは元表記を残してSolidへ正規化する。
2. 機関ごとに1件へ絞り、採用可能な評価数nを数える。nが2未満なら「評価不足」とする。
3. nが2または3のとき、D・R・Tのいずれかが採用数の過半数を占めれば、その方向を集計結果とする。D/Rは「D側優勢／R側優勢」、Tは「Toss Up」とする。
4. いずれも過半数にならない場合は「評価分裂」とする。Toss Upと評価分裂はともにグレーの未配分部分にまとめられるが、数字の内訳と説明は区別する。
5. 無所属候補などでD/Rの会派対応を確認できない評価は、推測でD/Rへ変換しない。「その他・会派未確認」として別区分へ保持する。対象が出現した場合も全議席の合計から落とさない。

| 有効な機関別の方向 | 結果 | 表示上の補足 |
|---|---|---|
| D・D・R | D側優勢 | 異論1機関を内訳に残す |
| D・D・T | D側優勢 | Toss Up評価を内訳に残す |
| R・R | R側優勢 | 採用2機関 |
| T・T・R | Toss Up | R評価を内訳に残す |
| D・R・T | 評価分裂 | 方向を割り当てない |
| D・R、またはD・T | 評価分裂 | 2機関が一致していない |
| Dのみ、または有効評価なし | 評価不足 | 接戦とは表示しない |

異なる機関が同じ世論調査を参照している可能性はあるため、「3機関だから3倍確か」とは説明しない。元のSolid・Lean等を数値化して平均し、合成した勝率や確信度を作る処理は追加しない。

### 5.4 欠測・時点・公開条件

図の近くに「集計基準日」「複数機関で評価できた選挙数／35」を表示する。完全収録なら短く1行でよい。原資料一覧、各機関の確認日、規則全文は「集計方法・出典」の初期状態で閉じた欄へ入れる。

最低2機関を確認できない選挙は、薄い斜線などの区分で数え、表示名を「評価不足」とする。グレーのToss Upへ加えない。一部不足時の見出しは「情勢評価の暫定集計（一部未取得）」とし、D/R側に割り当てられていない議席数を明示する。全35議席を保持し、合計を100へ無理に再配分しない。

正式な完了条件は、35選挙すべてに最低2機関の確認済み現行評価があること。取得制限などで不足する場合でもUIの他の改修は進め、最終報告では不足選挙と未完成の範囲を明示する。過去記事、推測値、現職維持の仮定で不足を埋めない。本書には新たな実データによる暫定議席数を記載していない。

## 7. 地図と州詳細のiPad横画面表示

### 7.1 表示モード

| 条件 | 地図と州詳細の配置 | スクロール |
|---|---|---|
| 幅960px以上・横長・表示高600px以上 | 地図を左、州詳細を右。表示可能な高さに収める | 右欄本文は枠内、ページ全体も通常どおり移動可能 |
| 幅または高さが不足、縦長の表示領域 | 地図の次に州詳細を1列で配置 | 通常のページスクロール |
| 文字拡大等で地図の操作と凡例を収められない | 1列表示へ切り替える | 内容を隠さず通常のページスクロール |

横画面の基本比率は地図55%・州詳細45%、列間24pxを初期値とする。左右の幅を実測し、地図の小さい州や州詳細の候補者選択が読める範囲で調整する。端末ごとの固定値ではなく、利用可能な幅・高さで切り替える。

### 7.2 高さと地図の保持

利用可能な高さHは、表示領域の高さから固定ヘッダー等の占有高と上下の余白を引いて求める。初期上限は860pxとし、iPadでは実際の表示可能な高さを優先する。100dvhを基本にし、対応しない環境は100vhへフォールバックする。必要な場合だけvisualViewportやResizeObserverを使い、ブラウザのツールバーや画面回転による変化を反映する。

左列には表示切替、州選択、地図、凡例を収める。地図は縦横比を保ち、凡例や操作を切り落とさない。長い「地図とシミュレーションの読み方」は左右の枠の下を横断する折りたたみ欄へ置き、地図を縮める原因にしない。

左の地図は、この地図・州詳細セクション内でのみ表示位置を保持する。右欄本文をスクロールしている間は動かず、ページ自体を後続のシミュレーションへ進めれば地図もセクションとともに画面外へ出る。ページ全体に地図を固定し続けたり、スクロール距離を増やすための空白を置いたりしない。

左右をH程度の同じ高さに収めれば、右欄の内部スクロール中は左が自然に残る。必要な追従はセクション内のposition: stickyで補い、右欄の長文に合わせて親セクションを際限なく高くしない。スクロール量を監視して地図を毎フレーム移動する処理は不要である。

### 7.3 右欄の構造

右欄は高さが制限された外枠、上部の固定見出し、本文のスクロール領域に分ける。

| 部分 | 内容・役割 |
|---|---|
| 外枠 | 明確な境界。H以内に収まり、長文や出典を開いても外枠は伸びない |
| 固定見出し | 州名、英語名等の短い補足、閉じる操作。高さを抑える |
| 本文 | 情勢の結論、候補者、仮定操作、主要争点、統計、履歴、出典。既存の読み順を保持 |
| スクロール表示 | 通常のスクロールバーを隠さない。残りがある場合は下端に小さな「下に続く」を表示してよい |

比較への追加ボタン、長い状態説明、評価日などは本文側に置き、固定見出しへ詰め込まない。本文中の候補者選択や折りたたみ欄は切り落とさない。本文の段落・候補者の主要説明は原則16px、補足は14pxとし、既存の小さい文字指定と!importantの競合を対象範囲で整理する。

構造上は既存の#detailを外枠として保ち、その内部に#state-detail-headerと#state-detail-scrollを設ける。スクロール対象にはmin-height: 0とoverflow-y: autoが必要となる。内部スクロールはこの一段に限定し、候補者カードや出典欄へさらに高さ固定のスクロールを重ねない。

### 7.4 操作ごとの位置保持

| 操作 | ページ全体 | 右欄本文 |
|---|---|---|
| 地図・州選択から別の州を選ぶ | 横画面では地図位置を維持 | 先頭へ戻し、新しい州の見出しをフォーカス |
| 同じ州で候補者・会派の仮定を変更 | 維持 | 読書位置と開いている詳細を保持 |
| 同じ州を比較に追加・解除 | 維持 | 読書位置と詳細の開閉状態を保持 |
| ニュース・8論点のパネルを開いて閉じる | 元の位置へ復元 | 元の位置へ復元 |
| 州詳細を閉じる | 不要なページ移動を避ける | 空の案内へ戻し、元の州選択操作へフォーカスを返す |
| 縦画面へ回転 | 選択中の州と仮定は保持 | 通常のページ上で読める位置に引き継ぐ |

現行のselectStateは同じ州の仮定変更や比較操作でも呼ばれ、#detailの内容を再生成する。したがって「selectStateを呼ぶたびにscrollTopを0へ戻す」実装は禁止する。再描画前に選択州IDを比較し、別州への変更と同じ州の更新を区別する。同じ州の更新では、スクロール位置・展開中のdetails・操作中のコントロールを安定した識別子で復元する。必要な箇所だけ更新できる場合は、本文全体の再生成を避ける。

画面回転時は、旧スクロール枠の先頭に見えていた本文要素を記録し、切り替え後に同じ箇所が読めるようにする。再描画で候補者の仮定、シナリオ、選択州をリセットしない。

### 7.5 ページ全体との関係

右欄上のスワイプ・ホイールは右欄を読み進める。枠外からの操作と、右欄の端での継続操作により、後続または前のページ部分へ自然に進めるようにする。右欄にoverscroll-behavior: containを無条件で付けたり、ページのbodyをロックしたりしない。本文上のtouchmoveをpreventDefaultしてスクロールを横取りする処理は追加しない。

右欄にはキーボードでもフォーカスできる入口と識別可能なラベルを付け、矢印・PageDown等で読み進められることを確認する。iPad Safariで右欄の端からページへ進めない場合は、その挙動を実機で確認してから修正する。ページ外枠を広く残すことと、後続のシミュレーションへの通常リンクにより退出経路を確保する。

prefers-reduced-motion時はページ移動やスクロール復元を即時実行する。右欄の更新で本文全体を長く読み上げないよう、既存のaria-live範囲を見直し、必要なら「選択州」と「議席更新」の短い通知を分ける。

- A07：集計の対象は通常33＋特別2の35議席。未取得や無所属の扱いがあっても合計100を維持し、不足をD/Rへ推測配分しない。
- A08：全35選挙の最低2機関収録と各資料の現行確認を実データで確認する。取得日と評価日を区別する。
- A09：候補者の仮定を変えても、冒頭の現在構成と全国の情勢集計が変わらない。利用者の仮定結果だけが変わる。

### 10.3 画面・操作の受け入れ確認

- A10：iPad横画面で制度と主な論点が2列になり、主な論点6文を省略せずに表示する。不要な空段落や本文の内部スクロールがない。
- A11：制度説明は両列を横断する幅で開き、長い出典を開いた後も上部の閉じる操作を使える。
- A12：制度パネルを新規に開くと出典は閉じている。閉じた後の読書位置・フォーカス・概説の開閉保存値を確認する。
- A13：主な論点の末尾から8論点が開く。本文・公開状態は変更されず、ニュースとの既存の往復も動く。
- A14：iPad横画面で右欄を最下部まで読んでも地図を見られる。長い出典を開いても右欄の外枠が伸びない。
- A15：別州へ切り替えると右欄だけが先頭へ戻る。同じ州の仮定変更・比較操作では読書位置と展開中の詳細が保たれる。
- A16：右欄の端・枠外からページの先へ進める。地図を含むセクションを離れると、後続の内容を地図が覆わない。
- A17：縦横回転・分割表示で、選択州・仮定・読んでいる内容が失われず、隠れたスクロール枠に本文が残らない。
- A18：iPhoneでは地図、州詳細の順で通常の縦スクロールになる。狭い枠の二重スクロールを強制しない。
- A19：キーボードで内訳、パネル、州選択、右欄を操作できる。スクリーンリーダーから数字と操作が消えない。
- A20：概説・権限表の開閉復元、候補者選択、自動保存、名前付き保存、共有URLの別タブ復元、州比較、逆算の適用・取消が動く。
- A21：#overview、#issues、#powers、#simulator、#map-headingの直接移動とブラウザの戻る・進むで、URLのsパラメータを維持する。
- A22：対象幅でページ全体の横はみ出し、数字や閉じるボタンの重なり、地図・凡例の欠落がない。

### 10.4 最小限の検証計画

既存のnpm testとnpm run buildを実行する。新規の自動テストは、複数機関の判定・重複排除・欠測・全体数・目標線など、間違うと表示の意味が変わる計算を中心にする。低影響の文言やCSS宣言をそのまま写すだけのテストは増やさない。

| 表示幅×高さ（CSS px） | 確認目的 |
|---|---|
| 1024×768 | 小さめのiPad横画面で2列と地図・右欄が成立するか |
| 1180×820 | iPad横画面の標準的な余白と本文量 |
| 1366×1024 | 大きいiPad横画面で地図だけ過大にならないか |
| 820×1180、1024×1366 | iPad縦画面で1列へ切り替わるか |
| 390×844 | iPhoneの読書順、文字、グラフ、小区分、パネル |
| 1440×900、1024×560 | PCの通常表示と高さ不足時のフォールバック |

ブラウザの画面幅変更による確認と、実機iPad Safariのタッチ・ブラウザツールバー・画面回転の確認は区別する。実機を使用できない場合は、代替確認した範囲を示し、実機の挙動を検証済みとは報告しない。特にA16とA17は実機確認の優先項目である。
