## 1. 目的と今回の範囲

読者が、現在の議席と改選範囲、選挙情勢、直近の動き、候補者の違いを順に理解し、自分で議席を変更した結果をその場で確認できるようにする。主対象はiPad横画面。iPhoneとiPad縦画面も、同じ内容と操作を読める構成にする。

| 利用者の項目 | 決定と実施範囲 |
| --- | --- |
| ① 可読性 | ニュースの見切れを修正。本文の文字サイズと操作領域を調整する |
| ② 8論点の内容 | 別チャットで検討。本文構成・追加調査は今回の対象外 |
| ③ 議席変更の反応 | 議席合計・変更内容・取り消しを操作位置の近くへ表示する |
| ④ 概説の順序 | 概説は冒頭に残す。全国情勢を先頭へ独立移動する旧提案は採用しない |
| ⑤ 合計議席 | 暫定配分の民主・共和・未配分の合計を明示する |
| ⑥ 候補者・州詳細 | 両候補を同じ項目で同時表示。州詳細を横・縦に広げる |
| ⑦ 文体・校正 | 詳細な文章校正は後の一括作業。今回必要なUI文言のみ変更する |
| ⑧ 注目州 | 州の表示を切替可能にする。優先順位・更新順の並替え機能は追加しない。Toss Upを説明し強調する |
| ⑨ 論点の共有 | 8論点の個別URL・読書位置の復元は保留 |
| ⑩ 制度・出典 | 制度の要点を先に示し、詳細説明と出典を展開して読む |
| ⑪ 全体配置 | 冒頭は左上に現在議席、左下に論点、右に上院情勢。次の段は「直近の更新」として左に注目州、右にニュース・予定 |

8論点の[別チャット検討用設計書](https://app.notion.com/p/3db340138e73813fa260e05ef40f6ac8?pvs=204)を参照する。①に伴う既存論点本文の文字サイズ調整のみ可読性改善に含め、内容・表示順・タブ・URLの再設計には着手しない。

本工程では、情勢評価の算出、候補者名簿、議席の基準版、採決要件、定期観測の設定を変更しない。未確認5情報源は別工程の残課題であり、このUI変更を再照合成功として記録しない。

## 2. 設計の根拠

直前の公開画面レビューではChrome 1363×936で次を確認した。実装時の回帰確認の起点とし、iPad実機の検証済み結果とは扱わない。

- ニュース一覧の各記事が縦方向に縮み、見出しが途中で欠ける。DOM上でも記事の内容高が表示高を超えていた。現行CSSでは横画面のカードに`flex-shrink: 0`がなく、`min-height: 0`が適用されている。
- 8論点の本文は約12px。全国情勢の長い前置き・注釈と、候補者比較の開閉が、重要な情報への到達を遅らせている。
- メーンの候補者選択後、議席集計は正しく変わるが、集計欄が表示範囲外にあり反応を見落としやすい。直前に戻す操作は動いた。
- 州詳細は固定高さの枠内をスクロールする構造。地図側には別の高さ上限と隠す指定があり、内容全体を基準とした高さ合わせになっていない。
- 冒頭の概説・議会権限の開閉記憶、ニュース・予定・州の往復、名前付き保存・共有などは既存機能として利用する。

参照：[現状確認](../CURRENT_STATE.md)、[前工程の実装記録](data-ui-analysis-implementation-20260914.md)、[前工程の検証記録](verification/ui-review-20260914.md)。

## 3. ページ構成と画面幅

### 3.1 iPad横の配置

タイトルと選挙日、サイトの短い説明は維持する。その下を以下の構成とする。

| 段 | 左側 | 右側 |
| --- | --- | --- |
| 概説 | 上：現在の議席と今回の改選範囲。下：選挙を見る主な論点と8論点への既存入口 | 全国情勢。上院の暫定配分、民主・共和それぞれの51議席への必要配分 |
| 直近の更新 | 注目州の切替と選択中の州の要約 | 最近のニュース／今後の予定 |
| 議席と権限 | 要点の一覧と、展開して読む詳細を全幅で表示 | 同左 |
| 地図・シミュレーション | 州選択、地図、凡例、地図の説明 | 選択した州の解説・候補者比較・当選仮定 |
| 後続機能 | 仮定の保存・比較、下院の既存機能、出典 | 同左 |

概説・直近の更新は左右1：1、間隔20〜24pxを起点とする。片側の文章量を揃えるための空白や固定文字数は設けない。国政情勢のブロックを移設し、旧位置に同じグラフを残さない。

### 3.2 レスポンシブ条件

- 横2列の基準は幅960 CSS px以上・横向き・高さ600 CSS px以上へ統一する。現行の944pxと960pxの境界の食い違いを解消する。
- 主な確認寸法：1180×820、1024×768、1366×1024。境界の959／960pxも確認する。
- iPad縦820×1180は1列。概説内は「現在議席→主な論点→上院情勢」、次の段は「注目州→ニュース・予定」の順。
- iPhone390×844、横844×390も1列。横画面だからという理由だけで2列へ戻さない。
- ブラウザーUI・キーボードによって表示高が減った場合は1列へ安全に切り替える。内容を切って高さへ押し込まない。

### 3.3 ナビゲーションと開閉

ページ内メニューは「概説・全国情勢」「直近の更新」「議席と権限」「地図・シミュレーション」「出典」。ニュースへ直接移動する既存リンクは維持する。

| URL・ID | 移設後の扱い |
| --- | --- |
| `#overview` | 冒頭の概説全体 |
| `#national-overview` | 冒頭右側の上院情勢。閉じた説明を経由せず到達可能にする |
| `#updates`（追加） | 「直近の更新」の見出し |
| `#news` | ニュース・予定。既存の個別記事リンクを維持 |
| `#powers` | 議席と権限。必要な説明の展開も維持 |
| `#simulator`、`#map-heading`、`#sources` | 既存の意味を維持 |
| `#issues` | 既存の8論点を開く動作を維持。新しい論点URL仕様は追加しない |

既存の概説開閉設定は左側の概説に適用し、右側の上院情勢は常時表示する。閉じた左側には見出しと開く操作を残す。記事URLに古い`#national-overview`が付いている場合は、`newsItem`の個別記事表示を優先する。ページ内移動で記事・州フィルター・保存案のURLパラメーターを落とさない。

## 4. 冒頭の議席表示をコンパクトにする

### 4.1 左側：現在議席と論点

現在議席の棒グラフは上院・下院の2本を維持。上院は非改選と今回改選、下院は全議席改選を区別する。現職の会派と選挙情勢を混ぜない。

下院の「多数派の目安」は既存の説明を短くまとめ、現在議席の下へ1行で配置する。右側に別の下院グラフを置く重複は解消する。値は既存データから取得する。

その下に既存の主な論点の短い概説を置く。重要語の太字と8論点を開く入口を保持し、詳細原稿は流し込まない。

### 4.2 右側：合計＋3本の上院グラフ

見出しは「上院の情勢と51議席への配分」。以下を順に表示する。

1. 「情勢評価による暫定配分」という短いラベルと、民主・共和・未配分の合計。
2. 暫定配分の横棒。薄色は非改選、濃色は改選。未配分を独立して示す。
3. 民主党会派が51議席に届く配分例。
4. 共和党会派が51議席に届く配分例。
5. 共通凡例と「配分の考え方・出典」を開く操作。

3本は同じ幅・全100議席の尺度で揃える。棒の高さは28〜32px、行間12〜16px、外側余白16px程度を起点とする。長い説明・大きなカード余白を減らし、本文を小さくして圧縮しない。

確認した基準版の表示例は「民主46／共和48／未配分6」。民主は非改選34＋今回17で51、共和は非改選31＋今回20で51となる。これらは本書の説明用数値であり、実装では既存の計算結果を使う。暫定配分から51までの差は、現在議席からの純増と呼ばない。

「非改選」「今回改選」「未配分」「配分未指定」は区別する。配分例の灰色は残りの行き先が未指定であることを示し、情勢上の接戦議席と混同させない。細い区間の文字が入らない場合は、棒の直下の直接ラベルで読めるようにする。

評価不足が生じた場合は未配分総数に含め、その内訳を示す。合計100との不一致を黙って隠さない。会派非所属等が存在する基準版では「その他」を省略しない。

### 4.3 展開する説明

「配分の考え方・出典」は初期状態で閉じる。内容は次の3群を一か所にまとめる。

- 2機関の評価から配分する方法、接戦・評価分裂・資料不足の扱い、勝率や確定結果ではないこと。
- 50対50時の副大統領と、51議席の例だけでは個別政策の成立を意味しないこと。既存の「議席と権限」へ接続する。
- 35選挙の評価内訳、機関名、資料ごとの確認日、原資料へのリンク。

説明を閉じても「情勢評価による暫定配分」「51議席への配分例」のラベルは見える。出典・確認日を削除せず、配置をまとめる。

## 5. 「直近の更新」：注目州とニュース・予定

### 5.1 注目州の切替

既存のToss Up・Leanの対象集合を維持する。確認時点では8選挙であり、詳説済み6選挙だけに減らさない。選挙の識別には`electionId`を使い、特別選挙も識別する。

- 州名のタブを上部に並べ、選んだ1州の要約を表示する。画面幅に応じてタブを折り返し、存在する州を発見しやすくする。
- 並び順は州名の英語順で固定し、勝ちやすさ・編集上の重要度・新着順の並替え機能を追加しない。
- タブには州名と接戦の印を示す。選択状態は塗り、接戦状態はバッジや輪郭で区別する。
- 本文は州名・評価、要約の見出し、2〜3文の既存要約、分析更新日、「州を詳しく読む」。詳説がない場合は既存資料への入口と準備中の表示を維持する。
- 州タブの操作はこの要約だけを切り替える。ニュースの州フィルターや議席の仮定を勝手に変更せず、ページも移動しない。
- 自動切替は行わない。ページ内では選択を保持し、ニュースを開いて戻っても元の州を表示する。新しい保存スキーマや専用URLは必須にしない。

### 5.2 Toss Upの説明と強調

注目州の見出し近くに「接戦・評価が分かれる州」を短く表示し、「Toss Upとは」をタップすると説明を開く。

表示文案：

> Toss Upは、どちらの候補・党が優勢かを判断しにくい選挙を示す。本サイトでは、評価機関が接戦とする選挙に加え、機関ごとの評価が分かれる選挙も同じ色で表示している。

各州の詳細ラベルは内部の集計分類を用いて「接戦（Toss Up）」と「評価が分かれる」を区別する。`split`は共和優勢と民主優勢の対立だけでなく、片方が接戦、他方が党派優勢の場合も含む。`missing`を接戦と表示しない。生の機関別評価は展開して確認できる。

接戦の強調には中立色のバッジと文字を使い、党派の青・赤、選択中の表示と区別する。注目州・地図の凡例・詳細欄で同じ説明を参照する。

### 5.3 ニュース・予定の見切れ修正

- 既存の統合フィード、2タブ、ページ送り、州フィルター、個別記事、戻る動作を維持する。
- すべての対象幅でカードを`flex-shrink: 0`とし、見出しの高さを内容に応じて確保する。見出しを固定高さで切らない。
- 見出し16px、要約・日付14pxを起点とする。概要は既存の2行省略を利用できるが、見出しは全文を表示する。
- iPad横では枠の高さ約400〜460px、iPhoneでは約3件が入口として見える高さを目安とする。長い見出しでも「必ず3件」に収めるための縮小・切断はしない。
- 内部スクロールはニュース一覧1か所。操作可能なスクロールバーと継続を示す手掛かりを残す。ページ送りは一覧の外に置く。
- ニュースと予定の優先順位付けは変更しない。「予定・予定」の重複などUI生成上の表記だけ整理可能。記事本文の一括校正は行わない。

## 6. 州詳細の拡大と候補者の同時比較

### 6.1 地図側を基準に高さを合わせる

iPad横では地図側と州詳細側を1：1、間隔20〜24pxで配置する。高さの基準は、左側の選択操作・地図・凡例・地図下の説明を含む全体とする。現行の780px上限や地図を小さく抑える指定に縛られない。

左側の自然な高さが行の高さを決め、右側がそこへ伸びる構造にする。右側の長文で行全体が際限なく伸びないよう、右の枠は外側のサイズから決める。CSSで右列内へ枠を配置して左列を高さの基準とする方法を第一候補とし、必要な場合のみ左列に限定したResizeObserverを使う。画面回転・説明の開閉・文字拡大後にも再計算する。

地図側の内容を`overflow: hidden`で隠さない。州詳細内は、固定の州見出しと、本文の縦スクロール1か所に分ける。候補者ごとの独立スクロールは作らない。地図と説明が画面高を超える場合はページ全体でもスクロールできる。

1列の画面では地図の後に州詳細を置き、固定高さと内部スクロールを解除する。空の州詳細を大きな空白のまま表示しない。

### 6.2 詳細欄の情報順序

1. 州名・選挙の種類・情勢ラベル。
2. 主要候補の氏名、党派、現職かどうか、既存資料にある短い経歴。
3. この州の要点と主要な判断材料。
4. 同じ項目での候補者比較。
5. 当選者の仮定、根拠、関連ニュース・予定、州の背景。

既存の「候補者比較」「当選者を選ぶ」「関連ニュース」へのショートカットを維持する。仮定の入力は長文をすべて読まなくても到達できるようにする。全候補・記名候補の選択肢は残す。

### 6.3 比較の構造

iPad横の詳細欄では主要2候補を常に左右の同じ列に置く。行ごとに比較項目の見出しを共通で示し、左右のセルを同じ高さへ揃える。候補者名・党派は比較部分を読む間に見失わないようにする。

初期表示は「経歴・地元」「政策・採決・発言」「政党・トランプとの関係」の3項目。既存の「実績への評価・批判」「有権者の受け止め」は補足として展開可能にする。展開操作は項目単位で両候補に同時に適用する。

狭い1列画面では、項目ごとに候補A→候補Bの順で隣接表示する。候補Aの全項目を読んだ後で候補Bへ移る構造は避ける。

表示のために未確認の政策を補作しない。既存の根拠が同じ政策について両候補を比較できない場合は、各セルを「公約」「採決実績」等で区別し、足りない比較は未確認として残す。本文の全面改稿は別途校正・調査工程へ引き継ぐ。

## 7. 議席変更の結果を操作中に表示する

### 7.1 共通の集計表示

上院の地図・州詳細を操作している間、短い「あなたの仮定」バーを表示する。合計は既存のScenarioStateから算出し、静的な情勢評価とは別の見出しにする。

- 民主・共和・未配分と、必要な場合のその他内訳、上院合計。
- 短い議席構成の横棒。党派と未配分が文字でも読めるようにする。
- 直近の変更と「直前に戻す」。

iPad横では地図・詳細の共通領域上部にstickyで配置し、既存のページ内メニューと重ならない位置にする。州詳細の内部をスクロールしても見える。画面高が小さい場合は合計と取り消しを優先する。

iPhoneでは地図・詳細の操作範囲内だけに小さい集計を表示し、safe-areaとソフトキーボードを考慮する。画面外の全ページに常時重ねず、入力欄と閉じる操作を覆わない。既存のモバイル専用集計と二重表示しない。

### 7.2 反応と取り消し

変更前後の同じ集計処理から差分を生成する。例：「メーンを民主党へ配分。民主＋1、未配分−1」。共和から民主への変更なら双方の増減を表示する。候補者だけを同会派内で変更した場合は「議席数の変化なし」とする。

複数州への経路適用は変更州数と合計の差をまとめる。プレビュー段階では本番の集計・保存値を変えない。取り消しは既存のUndo履歴へ接続し、別の履歴を新設しない。初期表示・記事閲覧・州切替を議席変更として扱わない。

表示は直近の操作結果として残し、次の操作で更新する。短時間で自動消去せず、`aria-live="polite"`で簡潔に通知する。入力フォーカスや州詳細のスクロール位置を集計更新で失わない。

全件リセット、未配分、無所属・会派未確認、保存案の読込み、共有URL、保存領域が利用できない場合も既存の意味を維持する。下院の操作を上院の増減として通知しない。

## 8. 制度説明・出典と文字の共通ルール

「議席と権限」の先頭では、法律・予算、人事、調査・監督の主要な作用を短く並べる。詳細8項目は項目単位で開けるようにし、条約・弾劾・拒否権・財政調整などの既存説明も読める状態を保つ。必要票と条件の説明は既存データを使う。

多数派の形成、通常法案の討論終結、個別の採決を一つの数値へまとめない。展開先にある「条件を確認」と経路表示への接続、既存の採決例は保持する。法律の新規解釈は今回追加しない。

本文16px、補足・日付14pxを基本とし、主要な操作領域は44px以上。候補者比較も左右表示のために本文を12pxへ戻さない。文字拡大時は折返しと1列への切替を許す。

根拠は本文の近くから開ける状態を保ち、同一ブロック内に繰り返される長い書誌情報をまとめる。本文と出典の対応や個別の資料確認日を失わない。サイト全体の更新日を全資料の確認日として使わない。
